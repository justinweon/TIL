# 0827 TIL — 데이터 분할과 스케일링으로 회귀를 평가하고 규제하기

집값은 면적 하나로만 정해지지 않아요. 학군, 범죄율, 건축 연도처럼 여러 특성을 함께 쓰면 더 많은 정보를 반영할 수 있습니다. 다만 특성을 늘리는 일과 새로운 데이터에서도 잘 예측하는 일은 같지 않아요. 이날은 다중회귀에서 출발해 공정한 평가 방법과 규제를 연결합니다.

## 1. 다중회귀에서 가중치를 읽는 법

$$
\hat y = w_1x_1 + w_2x_2 + \cdots + w_px_p + b
$$

단일 타깃을 예측하는 다중 선형회귀에서는 특성마다 가중치가 하나씩 있고 절편은 하나예요. 각 계수는 다른 특성을 고정했을 때 해당 특성이 한 단위 변하면 예측이 얼마나 달라지는지 나타냅니다. 입력 `X`와 정답 `y`는 같은 관측의 짝이 맞아야 해요.

면적과 범죄율은 단위가 다르므로 가중치의 절댓값만 보고 중요도를 비교하기 어렵습니다. 스케일을 맞추면 비교가 쉬워지지만, 그때도 계수를 인과적 영향이나 절대적인 중요도로 단정하지 않아요. 서로 비슷한 정보를 담은 특성끼리는 계수를 나눠 가질 수 있기 때문입니다.

> 정정: 다중공선성은 “특성이 많다”거나 “특성 하나가 빠지면 예측을 못한다”는 뜻이 아니라, 입력 특성들 사이에 강한 선형 관계가 있는 상태예요. 계수 추정이 불안정해질 수 있지만 과적합과 완전히 같은 개념은 아닙니다. 특성은 곧 원인이라는 뜻도 아니에요.

특성공학은 기존 특성을 조합하거나 변환해 새 표현을 만드는 전처리예요. 유용한 정보를 드러낼 수도 있지만 불필요한 항이 늘면 과적합 위험도 커집니다. 규제는 이런 상황에서 모델의 복잡도를 조절하는 선택지입니다.

## 2. 평가용 데이터를 먼저 떼어 두기

훈련 데이터는 파라미터를 학습하는 데, 검증 데이터는 모델 선택과 하이퍼파라미터 조정에, 테스트 데이터는 최종 평가에 사용해요. 원문의 분할을 적용하면 훈련·검증·테스트의 비율은 대략 64%·16%·20%입니다. 작은 데이터에서는 정수 개수로 나누는 과정에서 비율이 조금 달라질 수 있어요.

> 정정: 원문 앞부분은 이미 전체 데이터에서 만든 `x_scaled`를 분할하고, 뒤에서는 분할 전에 스케일링을 설명합니다. 전체 데이터의 평균·표준편차를 먼저 쓰면 검증·테스트 정보가 들어가므로 **분할 → 훈련 세트에서 전처리 학습 → 나머지는 변환만**의 순서로 고쳤어요.

검증 손실은 모델 선택과 조기 종료에 참고하지만, 일반적인 학습에서 검증 데이터의 기울기로 파라미터를 갱신하지 않습니다. 원문의 “검증 평가 → loss → optimizer”는 훈련 루프와 구분해야 해요.

무작위 분할은 독립적인 관측을 가정할 때 적절합니다. 시계열은 시간순 분할, 같은 대상의 반복 관측은 그룹 단위 분할이 필요할 수 있으므로 무조건 섞는 것은 아니에요.

## 3. 스케일링은 훈련 데이터의 기준을 공유하기

| 변환 | 식과 의미 |
|---|---|
| `MinMaxScaler` | `(x - 훈련 최솟값) / (훈련 최댓값 - 훈련 최솟값)`으로 학습 범위를 보통 0~1에 맞춰요. |
| `StandardScaler` | `(x - 훈련 평균) / 훈련 표준편차`로 표준화해요. |

원문의 `Standard Scalier`는 `StandardScaler`로 바로잡아요. 표준화는 학습 데이터의 평균을 0, 표준편차를 1에 맞추는 변환이지 분포를 정규분포로 바꾸는 작업은 아닙니다. 상수 열은 분산이 0이므로 일반 열과 다르게 처리돼요. `MinMaxScaler`로 변환한 새 데이터도 훈련 범위 밖이면 0보다 작거나 1보다 클 수 있습니다.

릿지·라쏘는 계수 크기에 벌점을 주므로 단위가 크게 다를 때 스케일링이 특히 중요해요. 다만 수학적으로 어떤 모델이든 무조건 스케일링해야 하는 것은 아닙니다.

아래는 원문 집값 예제를 순서와 변수명에 맞게 복구한 코드예요. `df`는 `YearBuilt`, `CrimeRate`, `SquareFeet`, `Price` 열이 있는 수치형 데이터로 준비돼 있어야 합니다. 데이터 파일이 제공되지 않아 **입력 의존적인 설명용 코드**로 남깁니다.

```python
from sklearn.model_selection import train_test_split
from sklearn.preprocessing import StandardScaler

# 이 필터는 원문 실습의 분석 대상을 유지합니다.
housing = df.loc[(df['YearBuilt'] > 2015) & (df['CrimeRate'] < 40)].copy()
X = housing[['SquareFeet']].to_numpy()
y_price = housing['Price'].to_numpy()

X_train_tmp, X_test, y_train_tmp, y_test = train_test_split(
    X, y_price, test_size=0.2, random_state=42
)
X_train, X_valid, y_train, y_valid = train_test_split(
    X_train_tmp, y_train_tmp, test_size=0.2, random_state=42
)

scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_valid_scaled = scaler.transform(X_valid)
X_test_scaled = scaler.transform(X_test)

print('전체:', X.shape)
print('훈련:', X_train.shape)
print('검증:', X_valid.shape)
print('테스트:', X_test.shape)
```

필터로 오래된 주택과 범죄율이 높은 지역을 제외했으므로 평가 결과를 모든 주택에 일반화할 수는 없어요. 결측값·잘못된 값의 점검과 최소 표본 수 확인도 별도로 필요합니다.

원문의 `.value`는 `.values` 또는 `.to_numpy()`로, `.flatten`은 실제 호출인 `.flatten()`으로 고칩니다. 다만 scikit-learn의 `X`는 보통 `(표본 수, 특성 수)`인 2차원 배열로 유지해요. 직접 작성하는 단일 특성 경사하강법에서만 1차원으로 펼치겠습니다.

## 4. 기본 모델을 학습하고 훈련·검증 오차 비교하기

먼저 규제 없는 모델을 기준으로 삼으면 규제가 필요한지 비교할 수 있어요. `LinearRegression`의 `coef_`는 학습된 계수이고 `intercept_`는 절편입니다. 이 API가 아래에서 직접 구현할 경사하강법을 그대로 실행한다고 생각하지는 않아요. 일반적인 최소제곱 선형대수 풀이를 사용합니다.

다음 코드는 앞 절의 분할·변환 결과를 이어 사용합니다.

```python
from sklearn.linear_model import LinearRegression, Ridge, Lasso
from sklearn.metrics import mean_squared_error, mean_absolute_error, r2_score

baseline = LinearRegression()
baseline.fit(X_train_scaled, y_train)
print('계수:', baseline.coef_)
print('절편:', baseline.intercept_)

for name, features, target in [
    ('훈련', X_train_scaled, y_train),
    ('검증', X_valid_scaled, y_valid),
]:
    prediction = baseline.predict(features)
    print(name, {
        'MSE': mean_squared_error(target, prediction),
        'MAE': mean_absolute_error(target, prediction),
        'R2': r2_score(target, prediction),
    })
```

MSE는 작은 쪽이 좋고, 보통의 `R²`는 큰 쪽이 좋아요. `R²`는 평가 데이터의 평균을 예측하는 기준과 비교하는 지표이며 음수가 될 수도 있습니다. 원문의 붙어 있던 MAE·`r2_score` 코드는 별도 호출로 분리했어요.

훈련 오차는 작은데 검증 오차가 크면 과적합을 의심해요. 그러나 분포 차이, 누수, 표본 부족도 함께 확인해야 하고 규제가 유일하거나 필수적인 해법은 아닙니다. 둘 다 좋지 않으면 과소적합, 부적절한 특성, 학습 부족 등을 살펴봐요. 단순히 학습 손실이 더 줄지 않는 상태를 과적합이라고 부르지는 않습니다.

## 5. 릿지와 라쏘는 오차가 아니라 계수에 벌점 주기

개념을 비교하는 목적함수는 다음처럼 쓸 수 있어요.

$$
J_{\mathrm{Ridge}}=\mathrm{MSE}+\alpha\sum_jw_j^2,
\qquad
J_{\mathrm{Lasso}}=\mathrm{MSE}+\alpha\sum_j|w_j|
$$

> 정정: 규제는 “큰 예측 오차에 더 큰 벌점을 추가”하는 것이 아니라 **가중치의 크기**에 벌점을 추가해요. MSE 자체가 오차를 벌하는 항이고, L1·L2는 파라미터를 벌하는 항입니다. 위 식은 비교용이며 라이브러리별 표본 수·상수 계수 관례가 달라 동일한 `alpha`가 같은 목적함수를 뜻하지는 않아요.

릿지(L2)는 계수를 전반적으로 축소하며 다중공선성이 있을 때 안정화에 도움이 될 수 있어요. 일반적으로 희소한 해를 만들지는 않지만 “계수가 절대로 정확히 0일 수 없다”는 절대적인 표현은 피합니다. 라쏘(L1)는 일부 계수를 정확히 0으로 만들어 변수 선택 효과를 낼 수 있어요. `alpha`가 너무 크면 필요한 정보까지 억제해 과소적합할 수 있습니다.

검증 데이터로 후보를 비교하고 나서 테스트를 한 번 사용합니다. 원문의 `alpha` 후보와 `Ridge`, `Lasso` API를 연결한 예시예요.

```python
candidates = [('선형회귀', baseline)]
for alpha in [0.01, 0.1, 1.0, 10.0, 100.0]:
    for model_class in [Ridge, Lasso]:
        model = model_class(alpha=alpha)
        model.fit(X_train_scaled, y_train)
        candidates.append((f'{model_class.__name__}(alpha={alpha})', model))

best_name, best_model = min(
    candidates,
    key=lambda item: mean_squared_error(
        y_valid, item[1].predict(X_valid_scaled)
    ),
)
# 후보 선택을 마친 뒤에만 최종 테스트 세트를 사용합니다.
y_pred = best_model.predict(X_test_scaled)
mse = mean_squared_error(y_test, y_pred)
mae = mean_absolute_error(y_test, y_pred)
rmse = mse ** 0.5
r2 = r2_score(y_test, y_pred)
print(best_name, {'MSE': mse, 'MAE': mae, 'RMSE': rmse, 'R2': r2})
```

여기서는 훈련 데이터로 학습한 후보 중 하나를 그대로 최종 평가합니다. 훈련·검증 데이터를 합쳐 재학습하려면 설정을 확정한 뒤 전처리도 그 합친 데이터에서 다시 학습하고 테스트에는 변환만 적용해야 해요. 테스트 결과를 보고 다시 후보를 고르면 최종 평가용 데이터의 역할이 사라집니다.

`RidgeCV`, `LassoCV`, `GridSearchCV`로 탐색을 자동화할 수도 있습니다. 교차검증에서는 각 폴드의 훈련 부분에서 전처리를 다시 학습해야 하므로, 스케일러와 모델을 `Pipeline`으로 묶어 교차검증하는 방식이 누수를 막는 데 도움이 됩니다.

## 6. 직접 구현해 보는 경사하강법

단일 특성에서는 MSE를 가중치와 편향으로 미분하는 과정을 직접 적어 볼 수 있어요.

$$
\frac{\partial J}{\partial w}=\frac{2}{N}\sum_i(\hat y_i-y_i)x_i,
\qquad
\frac{\partial J}{\partial b}=\frac{2}{N}\sum_i(\hat y_i-y_i)
$$

다음은 원문의 초기화와 루프를 연결한 코드입니다. 앞 절의 단일 특성 분할 결과에 의존하며, 실측 학습 결과는 제공하지 않아요. `epochs`는 실제 원문 코드의 `200`에 맞추고 설명에만 등장하던 `300`은 제외했습니다.

```python
import numpy as np
import matplotlib.pyplot as plt

x_train = X_train_scaled.ravel()
x_valid = X_valid_scaled.ravel()
y_train = np.asarray(y_train).ravel()
y_valid = np.asarray(y_valid).ravel()

weight = 0.0
bias = 0.0
learning_rate = 0.1  # 예제 설정값이며 일반적인 안정성을 보장하지 않습니다.
epochs = 200
train_losses = []
valid_losses = []
history_w = []
N_train = len(x_train)

for epoch in range(epochs):
    y_pred_train = weight * x_train + bias
    train_loss = np.mean((y_pred_train - y_train) ** 2)
    y_pred_valid = weight * x_valid + bias
    valid_loss = np.mean((y_pred_valid - y_valid) ** 2)

    # 두 손실과 가중치는 모두 현재 갱신 전의 상태를 기록합니다.
    train_losses.append(train_loss)
    valid_losses.append(valid_loss)
    history_w.append(weight)

    dw = (2 / N_train) * np.sum((y_pred_train - y_train) * x_train)
    db = (2 / N_train) * np.sum(y_pred_train - y_train)
    weight -= learning_rate * dw
    bias -= learning_rate * db

# 원문의 시각화 주제에 맞게 추가한 설명용 그래프 코드입니다.
fig, ax = plt.subplots()
ax.plot(train_losses, label='훈련 손실')
ax.plot(valid_losses, label='검증 손실')
ax.set_xlabel('갱신 전 에포크 인덱스')
ax.set_ylabel('MSE')
ax.legend()
```

`x_train`만 2차원이고 `y_train`이 1차원이면 의도치 않은 브로드캐스팅으로 표본끼리 모든 조합의 오차를 만들 수 있어요. 이 단일 특성 예시는 둘 다 1차원으로 맞춰 그 문제를 피합니다. Matplotlib import도 `import matplotlib as plt`에서 `import matplotlib.pyplot as plt`로 고쳤어요.

한 에포크는 전체 훈련 데이터를 한 번 사용하는 단위입니다. 위 코드는 전체 배치를 한 번에 사용하므로 에포크마다 한 번 갱신하지만, 미니배치 학습에서는 한 에포크에 여러 갱신이 일어나요. 검증 손실은 기록만 하고 `dw`, `db`에는 사용하지 않습니다. 마지막 손실 기록은 마지막 갱신 직전이므로 최종 파라미터의 손실과 구분해요.

> 정정: 스케일링만 했다고 학습률 `0.1`이 언제나 안전한 것은 아닙니다. 목적함수와 데이터에 따라 달라요. SGD는 임의의 최저점을 찍는 방법이 아니며 Adam도 전역 최솟값을 보장하지 않습니다. 편미분은 그림이 3차원일 때부터 쓰는 기법이 아니라, 여러 변수의 함수에서 한 변수에 대한 변화를 다루는 미분이에요.

## 7. 다른 규제와 원문 질문 연결하기

Dropout은 신경망 학습 중 일부 활성값을 무작위로 0으로 만드는 규제이고, early stopping은 검증 성능을 보며 학습을 멈추는 절차예요. 둘 다 일반화를 돕기 위한 방법이지만 릿지·라쏘와 적용 위치가 다릅니다. 조기 종료는 과적합이 시작되는 순간을 정확히 아는 장치가 아니라 검증 지표와 허용 대기 횟수 등에 의존하는 판단이에요.

### 강의 밖 질문: 라쏘에서 “미미한 특성”은 상대적인가요?

어떤 고정 중요도 기준 아래의 특성을 단순 삭제하는 것은 아니에요. 다른 특성이 이미 설명하는 정보, 데이터의 스케일, `alpha`와 예측 오차의 균형에 따라 최적화 결과로 계수가 0이 됩니다. 강하게 상관된 특성들 중 하나만 남을 수도 있으므로 “0이 된 특성은 현실에서도 무의미하다”고 해석하면 안 됩니다.
