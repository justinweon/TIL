## 1. 반복문에서 의도가 드러나는 표현으로

여러 값을 처리할 때 반복문을 직접 작성해도 되지만, 변환이나 선택처럼 자주 쓰는 작업은 더 짧게 표현할 수 있어요. `map()`은 각 요소에 함수를 적용하고, `filter()`는 조건을 만족하는 요소를 남깁니다. Python 3에서는 둘 다 결과를 차례로 소비하는 iterator를 반환해요. 간단한 식이라면 리스트 컴프리헨션으로 의도를 더 쉽게 읽을 수도 있습니다.

```python
nums = [*range(1, 11)]
nums2 = [x ** 2 for x in nums]
nums3 = [x for x in nums if x % 2 == 1]
print(nums2)
print(nums3)

squares = list(map(lambda x: x ** 2, nums))
odds = list(filter(lambda x: x % 2 == 1, nums))
print(squares, odds)
```

`*range(...)`는 이 문맥에서 iterable의 값을 펼칩니다. `lambda`는 간단한 익명 함수를 만드는 표현식이에요. 원문의 `.map()`은 여기서는 객체 메서드가 아닌 내장 함수 `map()`을 가리킵니다.

번호가 필요하면 카운터를 직접 증가시키기보다 `enumerate()`로 번호와 값을 함께 받을 수 있어요.

```python
fruits = ["사과", "바나나", "복숭아", "체리"]
for item in enumerate(fruits):
    print(item)

for i, fruit in enumerate(fruits, start=1):
    print(i, fruit)
```

`enumerate()`는 기본적으로 0부터 시작하는 번호와 요소를 튜플로 제공합니다. 원문의 `fruits = item[1]`은 목록 이름을 개별 과일 값으로 덮어쓰므로 `fruit`로 구별했어요. 본문이 없던 반복문에도 출력 문장을 넣었습니다.

두 목록의 같은 위치에 있는 값을 묶을 때는 `zip()`이 자연스럽습니다.

```python
from itertools import zip_longest

persons = ["김철수", "김영희", "김민수"]
fruits = ["사과", "오렌지", "멜론"]
items = zip(persons, fruits)
print(list(items))
print(list(zip_longest(persons, fruits[:2], fillvalue="미지정")))
```

`zip()`은 기본적으로 가장 짧은 입력이 끝나면 멈추고, `zip_longest()`는 가장 긴 입력에 맞춰 부족한 자리를 `fillvalue`로 채웁니다. 원문의 인덱싱 반복문도 길이가 같을 때는 가능하지만, 짧은 목록을 인덱스로 접근하면 `IndexError`가 날 수 있어요.

## 2. 정렬과 최솟값은 서로 다른 작업이에요

`list.sort()`는 원본 리스트를 제자리에서 정렬하고 `None`을 반환해요. `sorted(iterable)`은 원본을 바꾸지 않고 정렬된 새 리스트를 돌려줍니다.

```python
import random

nums = [*range(1, 11)]
random.shuffle(nums)
nums_sorted = sorted(nums)
print("새 정렬 결과:", nums_sorted)
print("원본:", nums)
nums.sort()
print("원본을 정렬한 뒤:", nums)
print(min(nums), max(nums))

fruits = ["사과", "오렌지", "멜론", "복숭아"]
print(min(fruits), max(fruits))
```

> 정정: `sorted()`의 결과는 불변 객체가 아니라 변경 가능한 리스트예요. `min()`과 `max()`는 정렬 결과의 양 끝과 같은 값을 찾지만, 내부적으로 전체 정렬이 필요한 함수는 아닙니다. 원문의 `NUMS`와 `nums`도 하나로 맞췄습니다.

문자열 비교는 기본적으로 유니코드 코드 포인트에 따른 사전식 비교입니다. 사람의 언어권별 정렬 규칙과 항상 일치하는 것은 아니에요. 무작위 섞기의 구체적인 결과는 실행마다 달라질 수 있어 원문의 출력 순서를 재현 결과로 싣지 않았습니다.

## 3. JSON 문자열과 Python 객체 사이 오가기

Python 딕셔너리를 다른 프로그램과 주고받으려면 서로 이해할 수 있는 표현이 필요해요. JSON 직렬화는 지원되는 Python 값을 JSON 형식으로 바꾸고, 역직렬화는 JSON을 Python 값으로 읽는 과정입니다.

```python
import json

user = {"name": "김철수", "age": 20}
json_string = json.dumps(user)
json_string_readable = json.dumps(user, ensure_ascii=False)
print(json_string, type(json_string))
print(json_string_readable)

nums_string = "[1, 2, 3, 4, 5]"
user_string = '{"name": "김철수", "age": 20}'
nums = json.loads(nums_string)
user2 = json.loads(user_string)
print(nums, type(nums))
print(user2, type(user2))
```

`dumps()`와 `loads()`는 문자열을 대상으로 합니다. `ensure_ascii=False`는 한글을 그대로 읽기 좋게 남기는 옵션이지, JSON 문자열의 의미를 바꾸는 옵션은 아니에요. JSON의 `\uXXXX`는 이스케이프 표현입니다. 유니코드 전체가 16비트 문자 체계라는 원문의 설명은 정확하지 않아요. 또 JSON 역직렬화의 결과는 입력에 따라 리스트나 숫자 등이 될 수도 있으므로 항상 딕셔너리는 아닙니다.

## 4. 실행 인자와 날짜·시간 살펴보기

```python
import sys

print(sys.argv)
```

스크립트로 실행할 때 `sys.argv`에는 보통 스크립트 이름과 명령줄 인자가 문자열로 들어옵니다. 실행 방식에 따라 첫 항목은 달라질 수 있어요. 원문의 `os/sys` 탭에는 `sys.argv` 코드만 있어서 `os`의 구체적인 활용은 임의로 추가하지 않았습니다.

`datetime` 모듈은 값이 담는 범위에 따라 클래스를 나눠요.

| API | 담는 값과 주의점 |
| --- | --- |
| `datetime.datetime` | 날짜와 시간을 함께 다뤄요. 호환되는 값끼리 뺄 수 있어요. |
| `datetime.date` | 날짜를 다루며 날짜 간 뺄셈은 기간을 반환해요. |
| `datetime.time` | 하루 안의 시각을 표현해요. 두 `time` 객체를 직접 뺄 수는 없습니다. |
| `datetime.timedelta` | 날짜·시간의 차이인 기간을 표현해요. |

> 정정: 원문의 `time.delta`는 `datetime.timedelta`입니다. 시각 차이를 구하려면 날짜와 결합한 `datetime` 등을 사용하고, 자정을 넘는지와 시간대 조건도 정해야 해요.

## 5. 파일은 읽은 뒤 정리하는 것까지 한 작업이에요

입력은 파일의 데이터를 프로그램으로 읽어 오는 것이고, 출력은 프로그램의 데이터를 파일에 쓰는 것이에요. `open()`으로 파일 객체를 얻은 뒤 `read()`나 `write()`를 호출합니다. 직접 열었다면 예외가 발생하는 경우까지 고려해 `close()`를 호출해야 해요. 파일을 닫으면 쓰기 버퍼를 비우고 파일 자원을 정리합니다.

대부분은 `with open(...)`으로 정리 시점을 함께 표현하는 편이 좋아요. 아래는 실행하면 예제 파일을 생성하거나 덮어쓰는 설명용 코드이며, 문서를 만드는 과정에서는 실행하지 않았습니다.

```python
with open("text.txt", "w", encoding="UTF-8") as fp:
    fp.write("안녕하세요.")
    fp.write("반갑습니다.")

with open("text.txt", "a", encoding="UTF-8") as fp:
    fp.write("\n다음 줄입니다.\n")
```

`w`는 기존 파일을 열 때 내용을 지우고 새로 쓰는 모드이며, `a`는 끝에 덧붙이는 모드예요. 단순히 파일 포인터의 위치만 다르다고 이해하면 덮어쓰기 위험을 놓치기 쉽습니다. `write()`는 줄바꿈을 자동으로 넣지 않으므로 필요한 위치에 `\n`을 적습니다.

이 정리 동작의 배경에는 컨텍스트 매니저가 있어요.

```python
class MyResource:
    def __enter__(self):
        print("자원 사용을 시작합니다.")
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        print("자원 사용을 마칩니다.")
        return False


with MyResource() as resource:
    print(type(resource).__name__)
```

`__enter__()`의 반환값이 `as` 뒤의 이름에 연결되고, 블록을 떠날 때 `__exit__()`가 호출됩니다. 예외가 있으면 그 정보도 전달돼요. 여기서는 `False`를 반환하므로 예외를 억제하지 않습니다. 단, `__enter__()` 자체가 실패하면 해당 컨텍스트의 `__exit__()`는 호출되지 않아요.

> 정정: `open()` 자체가 클래스인 것은 아닙니다. 파일 객체를 반환하는 내장 함수이고, 반환된 객체가 컨텍스트 매니저 규약을 지원합니다. `with`는 파일만을 위한 구문도 아니에요.

## 6. 읽는 크기에 따라 메모리 사용도 달라져요

| 읽기 방식 | 반환과 용도 |
| --- | --- |
| `read()` | 인자 없이 호출하면 남은 내용을 하나의 문자열로 읽어요. |
| `readline()` | 다음 한 줄을 읽고, 파일 끝에서는 빈 문자열을 반환해요. |
| `readlines()` | 남은 줄을 모두 읽어 문자열 리스트로 만들어요. |
| `for line in fp` | 파일 객체를 직접 반복하면서 한 줄씩 처리해요. |

```python
with open("text.txt", "r", encoding="UTF-8") as fp:
    text = fp.read()
    print(text)

with open("text.txt", "r", encoding="UTF-8") as fp:
    first_line = fp.readline()
    print(first_line, end="")

with open("text.txt", "r", encoding="UTF-8") as fp:
    lines = fp.readlines()
    print(lines)

with open("text.txt", "r", encoding="UTF-8") as fp:
    while (text := fp.readline()):
        print(text, end="")

with open("text.txt", "r", encoding="UTF-8") as fp:
    for line in fp:
        print(line, end="")
```

`:=`는 값을 대입하면서 그 값을 표현식으로 사용할 수 있게 하는 대입 표현식입니다. 판단 전용 연산자는 아니에요. 위 `while`은 한 줄을 읽어 `text`에 담고, 그 값이 빈 문자열인지에 따라 반복을 이어갑니다. 파일의 빈 줄은 보통 `"\n"`이라 파일 끝의 `""`와 달라요.

직접 반복하면 전체 줄 목록을 만들지 않아서 대용량 파일에 유리합니다. 내부 버퍼는 여전히 사용하며, 한 줄 자체가 매우 크면 그만큼의 메모리는 필요해요. 줄에 이미 줄바꿈이 들어 있으므로 `print(..., end="")`를 사용해 빈 줄이 추가되는 것도 피했습니다.

## 7. CSV와 JSON 파일에 구조를 보존하기

CSV는 쉼표로 구분한 값들을 행 단위로 저장하는 형식이에요. `csv.writer()`의 `writerow()`로 한 행을 쓰고, `csv.reader()`로 행을 읽을 수 있습니다. 쉼표나 따옴표가 있는 값도 직접 문자열을 이어 붙이기보다 라이브러리에 맡기는 편이 안전해요.

```python
import csv

with open("members.csv", "w", encoding="UTF-8", newline="") as fp:
    writer = csv.writer(fp)
    writer.writerow(["name", "age", "mobile"])
    writer.writerow(["예시 사용자", 20, "예시 연락처"])

with open("members.csv", "r", encoding="UTF-8", newline="") as fp:
    for row in csv.reader(fp):
        print(row)
```

파일 이름의 `memers.csv`는 `members.csv`로 정리했고, 잘못된 `UTF=8`은 `UTF-8`로 고쳤어요. CSV 파일은 `newline=""`를 지정해 운영체제와 CSV 모듈의 줄바꿈 처리가 겹치지 않게 합니다. 기본 reader는 필드를 문자열로 반환하므로 나이가 자동으로 정수가 되는 것은 아니에요. 예시 연락처도 실제 정보처럼 보이지 않는 값으로 바꿨습니다.

JSON을 파일로 다룰 때는 `dump()`와 `load()`를 사용해요.

```python
import json

user = {"name": "예시 사용자", "age": 20, "mobile": "예시 연락처"}
with open("user.json", "w", encoding="UTF-8") as fp:
    json.dump(user, fp, indent=4, ensure_ascii=False)

with open("user.json", "r", encoding="UTF-8") as fp:
    user2 = json.load(fp)
    print(user2, type(user2))
```

`indent=4`는 중첩 단계마다 들여쓰기 폭을 지정해 읽기 좋은 파일을 만듭니다. 문자열용 `dumps`/`loads`와 파일 객체용 `dump`/`load`를 구분해 두면 API 이름을 덜 헷갈릴 수 있어요.

## 8. 대기 시간이 길어지면 비동기를 생각해요

파일과 네트워크 작업에는 결과를 기다리는 시간이 생깁니다. 동기 함수가 끝날 때까지 다음 호출을 미루면 흐름은 단순하지만, 서로 독립적인 대기를 겹칠 기회를 놓칠 수 있어요.

```python
import time


def work(title, seconds):
    time.sleep(seconds)
    print(title, "완료!")


start = time.perf_counter()
work("작업A", 2)
work("작업B", 3)
work("작업C", 1)
print("걸린 시간:", time.perf_counter() - start)
```

비동기 예제는 기다리는 동안 이벤트 루프가 다른 작업을 진행하도록 합니다.

```python
import asyncio
import time


async def async_work(title, seconds):
    await asyncio.sleep(seconds)
    print(title, "완료")


async def main():
    start = time.perf_counter()
    await asyncio.gather(
        async_work("작업A", 2),
        async_work("작업B", 3),
        async_work("작업C", 1),
    )
    print("걸린 시간:", time.perf_counter() - start)


if __name__ == "__main__":
    asyncio.run(main())
```

`async def`를 호출하면 코루틴 객체를 얻습니다. `main()`만 적는 것으로 본문 실행이 끝나지 않아요. 일반 스크립트에서는 `asyncio.run(main())`으로 이벤트 루프를 실행하고, 이미 루프가 돌아가는 노트북에서는 지원되는 환경에 한해 `await main()`을 사용합니다.

`await`는 현재 코루틴이 결과를 기다리는 표현이에요. 대기가 필요할 때 이벤트 루프가 다른 준비된 작업을 실행할 수 있지만, 프로세스 전체를 얼리는 명령은 아닙니다. 반대로 `async def` 안에 `time.sleep()`이나 무거운 계산을 넣으면 이벤트 루프를 막을 수 있어요. 일반 제너레이터의 `yield`도 상태를 보존하며 제어권을 넘기지만, 그것만으로 비동기 작업이 되는 것은 아닙니다.

| 비교할 점 | 동기 처리 | 비동기 처리 |
| --- | --- | --- |
| 순서 | 호출 결과를 받은 뒤 다음 작업으로 진행하기 쉬워요. | 독립적인 작업의 대기를 겹칠 수 있어요. |
| 적합한 상황 | 짧고 순차적인 스크립트에 간단해요. | 네트워크 등 대기가 긴 I/O 작업에 유리할 수 있어요. |
| 비용과 한계 | 많은 대기가 쌓이면 처리량이 낮아질 수 있어요. | 취소·예외·동시성 관리가 필요하고 CPU 연산을 저절로 병렬화하지는 않아요. |

원문의 정확한 경과 시간은 측정 환경에 의존하므로 옮기지 않았습니다. 동기 예제는 대기를 순서대로 거치고, 비동기 예제는 겹쳐 기다린다는 구조만 설명해요. 두 예제 모두 여기서 실행하지 않았습니다.

## 9. 강의 밖 질문과 확인하지 못한 자료

원문의 “`__new__`가 `__init__`보다 앞서는가?”에는 일반적인 인스턴스 생성에서 그렇다고 답할 수 있어요. `__new__`가 객체를 만들고, 적절한 인스턴스를 반환하면 `__init__`이 초기화합니다. F12로 정의를 찾아보는 것은 API의 인자와 동작을 확인하는 학습 방법으로 남겨 두었어요.

`sys.argv`와 `with open` 관련 이미지 전용 내용은 미확인입니다. 만료되는 서명 이미지 URL을 싣지 않고 [원문 0820](https://www.notion.so/3b7eb86ebd7380e59ef3ee2ad3231aad)을 남깁니다. 이미지의 화면이나 출력 내용을 추정해 복원하지 않았어요.

[머신러닝 예습 특강](https://app.notion.com/p/3bff20789cb180f690dec834555ec5f0)과 [강의 예제 하위 페이지](https://app.notion.com/p/3b7eb86ebd73804d82ccc94bafb04a87)는 링크만 제공되어 본문을 확인하지 않았습니다. Python 코드의 확인 범위는 문법 검사이며, 파일 읽기·쓰기와 비동기 실행 결과는 검증하지 않았어요.
