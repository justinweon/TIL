## 1. 반복에서 객체로 이어지는 흐름

반복 가능한 데이터를 다룰 때는 값을 어디에 보관하고 언제 꺼낼지 생각하게 돼요. iterable은 반복 가능한 객체이고, `iter()`로 얻은 iterator는 `next()`가 호출될 때 다음 요소를 내줍니다. 일반적으로 `__iter__`와 `__next__`가 이 약속을 구현해요. 마지막 요소까지 소비하면 발생하는 예외의 이름은 `StopIteration`입니다.

제너레이터 함수는 호출할 때 모든 결과를 만들지 않고, 반복을 진행하다 `yield`를 만나면 값을 전달하고 실행 상태를 보관해요. 리스트 컴프리헨션이 결과를 한꺼번에 만드는 것과 달리 필요한 시점에 값을 만들 수 있어서, 전체 결과를 저장하지 않는 경우 메모리를 아낄 수 있습니다.

> 정정: 원문의 `StopIterationError`는 `StopIteration`이에요. 리스트 컴프리헨션과 제너레이터의 차이는 동기와 비동기가 아니라 즉시 평가와 지연 평가입니다. 일반 제너레이터가 저절로 비동기로 실행되지는 않아요.

외부 코드를 가져오는 `import`, 출처를 지정하는 `from`, 별칭을 붙이는 `as`도 함께 복습했어요. 패키지는 [PyPI](https://pypi.org/)에서 찾을 수 있고, uv 프로젝트에서는 `uv add 패키지명`으로 의존성을 추가할 수 있습니다. 여기서 `패키지명`은 실제 이름으로 바꿔야 하는 자리이며, 이 노트에서는 설치를 실행하지 않았어요.

## 2. 클래스는 상태와 행동을 함께 정의해요

버스를 표현하려면 승객 수 같은 상태뿐 아니라 타고 내리는 행동도 필요해요. 객체지향 프로그래밍은 이렇게 관련된 상태와 행동을 객체에 묶고, 객체들이 협력하도록 프로그램을 구성하는 방식입니다. 버스 객체가 승객 객체를 보관하면 두 객체의 관계도 코드에 드러나요.

클래스는 객체의 구조와 행동을 정의하고, 클래스를 호출해 만든 개별 객체를 그 클래스의 인스턴스라고 불러요. 클래스 이름에는 `Bus`처럼 대문자로 시작하는 PascalCase를 쓰는 관례가 있지만 문법상 강제되는 규칙은 아닙니다. 속성은 객체에 붙은 이름이며 인스턴스 변수보다 넓은 개념이고, 메서드는 객체나 클래스와 연결되는 함수입니다.

아래는 원문의 여러 버스 예제를 하나로 정리하고 하차 처리를 고친 코드예요.

```python
class Passenger:
    pass


class Bus:
    def __init__(self):
        self.count = 0
        self.passenger = []

    def ride(self, passenger):
        self.passenger.append(passenger)
        self.count += 1
        print("탑승")

    def off(self, passenger):
        if passenger not in self.passenger:
            raise ValueError("이 버스에 탑승한 승객이 아닙니다.")
        self.passenger.remove(passenger)
        self.count -= 1
        print("하차")

    def show_count(self):
        print("승객 수:", self.count)

    def print_self(self):
        print(id(self))


bus1 = Bus()
bus2 = Bus()
p1 = Passenger()
p2 = Passenger()
bus1.ride(p1)
bus1.ride(p2)
bus1.off(p1)
bus1.show_count()
print(bus1 is bus2)
print("bus1 식별값:", id(bus1))
bus1.print_self()
```

`bus1`과 `bus2`는 같은 클래스로 만들었지만 별개의 인스턴스예요. `self.passenger = []`를 초기화 메서드 안에 두었기 때문에 승객 목록도 각각 만들어집니다. `self`는 메서드를 호출한 인스턴스를 받는 매개변수의 관례적인 이름이에요. `bus1.print_self()`에서는 그 인스턴스가 자동으로 첫 인자로 전달됩니다.

> 정정: 원문의 `if self.count > 1`은 마지막 승객의 하차를 막고, `self.passenger.remove(self.passenger)`는 승객이 아니라 목록 자체를 지우려는 코드예요. 하차할 승객을 매개변수로 받아 제거하도록 바꿨습니다. 실제 설계에서는 `len(self.passenger)`로 수를 계산하면 목록과 `count`가 어긋날 위험도 줄일 수 있어요.

`__init__`은 이미 만들어진 인스턴스의 초기 상태를 설정합니다. 객체 생성 자체는 `__new__`가 담당해요. `self`는 주소를 직접 계산하는 기능도, 클래스 안에서만 쓸 수 있는 특별한 키워드도 아닙니다. `id()`는 객체의 식별값을 반환하며, 메모리 주소라는 해석은 CPython의 구현 세부 사항입니다.

원문의 힙과 호출 스택 설명은 클래스도 객체라는 점을 이해하기 위한 보조 설명으로 남겨 두면 좋아요. Python에서 클래스 정의를 실행하면 클래스 객체가 만들어지고, 이름은 객체를 참조합니다. CPython의 `PyCodeObject`, `PyTypeObject`, `PyFrameObject`는 각각 코드, 타입, 실행 프레임과 관련된 구현 구조이지만 모든 Python 구현의 공통 메모리 배치 규칙은 아니에요. 프레임이나 객체가 반드시 호출 직후 사라지는 것도 아닙니다. CPython은 참조 카운팅과 순환 참조 수집을 함께 사용해요.

## 3. 객체를 읽기 좋은 문자열로 표현하기

객체를 출력할 때 내부 상태를 읽을 수 있으면 확인하기가 편해져요. `__str__`은 사람이 읽기 좋은 표현을, `__repr__`은 개발자가 객체를 식별하고 디버깅하기 좋은 표현을 담당합니다.

```python
import datetime

example_date = datetime.date(2026, 8, 18)
print(str(example_date))
print(repr(example_date))


class User:
    def __init__(self, name):
        self.name = name


class VIPUser(User):
    def __init__(self, name, point):
        super().__init__(name)
        self.point = point

    def __str__(self):
        return f"name={self.name}, point={self.point}"

    def __repr__(self):
        return f"VIPUser(name={self.name!r}, point={self.point!r})"


user = VIPUser("원정린", 20)
print(user)
print(repr(user))
```

`print(user)`는 문자열 표현을 구하고, 별도의 `__str__` 구현이 없으면 기본 동작이 `__repr__`을 이용합니다. 이는 로깅의 중요도에 따라 우선순위를 정하는 규칙이 아니에요. 재생성 가능한 표현은 좋은 `repr`의 목표일 수 있지만 모든 객체에서 보장되지는 않습니다. 문자열을 Python 표현식으로 평가하는 `eval()`에 외부 입력을 넘기면 임의 코드 실행 위험이 있으므로, 객체 표현을 확인하려고 `eval()`을 쓸 필요는 없어요.

## 4. 상속은 공통 행동을 재사용하는 관계예요

동물이라는 공통 개념에 `kind`와 `move()`를 정의하고, 강아지와 고양이에서 움직임을 구체화할 수 있어요. 하위 클래스가 같은 이름의 메서드를 다시 정의하는 것을 오버라이딩이라고 합니다.

```python
class Animal:
    def __init__(self, kind):
        self.kind = kind

    def move(self):
        print("동물이 움직입니다.")


class Dog(Animal):
    def __init__(self):
        super().__init__("강아지")

    def move(self):
        print("강아지 걸음으로 움직입니다.")


class Cat(Animal):
    def __init__(self):
        super().__init__("고양이")

    def move(self):
        print("고양이 걸음으로 움직입니다.")


class Human:
    def move(self):
        print("두 발로 직립 보행합니다.")


dog = Dog()
cat = Cat()
dog.move()
cat.move()
print(dog.kind, cat.kind)
print(isinstance(dog, Animal))
print(isinstance(Human(), Animal))
print(issubclass(Dog, Animal))
```

자식 클래스에서 `move()`를 정의하지 않으면 상위 클래스의 구현을 찾습니다. `isinstance(obj, Class)`는 상속 관계를 포함해 인스턴스 여부를 검사하고, `issubclass(Child, Parent)`는 클래스 사이의 관계를 검사해요.

> 정정: `super()`는 별도의 부모 객체를 생성하지 않습니다. 같은 인스턴스에 대해 MRO의 다음 클래스에서 메서드를 찾는 프록시를 반환해요. 키워드도 아닙니다. 부모 구현을 부를 때 `super().move()`를 쓰면 협력적 상속을 유지하기 좋고, `Animal.move(self)`처럼 직접 호출하는 방법도 있지만 다중 상속에서는 주의해야 합니다.

다중 상속에서는 메서드를 어느 순서로 찾는지도 알아야 해요.

```python
class ParentA:
    def a(self):
        print("ParentA - a()")

    def b(self):
        print("ParentA - b()")


class ParentB:
    def a(self):
        print("ParentB - a()")

    def c(self):
        print("ParentB - c()")


class Child(ParentA, ParentB):
    pass


child = Child()
child.a()
child.b()
child.c()
print(Child.mro())
```

이 단순한 예에서는 `a()`를 `ParentA`에서 찾지만, 복잡한 계층까지 무조건 왼쪽 부모부터 끝까지 탐색하는 것은 아니에요. Python은 C3 선형화로 MRO를 구성합니다. `Child.mro()`는 리스트, `Child.__mro__`는 튜플을 반환해요. 다이아몬드 상속도 MRO만 있으면 초기화가 저절로 해결되는 것은 아니므로, 참여하는 클래스가 `super()` 호출 규약과 인자 전달 방식을 맞춰야 합니다.

원문의 확장 항목은 다음처럼 구분할 수 있어요.

| 개념 | 연결해서 기억할 점 |
| --- | --- |
| 단일·다중·다단계·계층적 상속 | 부모의 수와 상속 계층의 모양을 구분하는 이름이에요. |
| `ABC`, `abstractmethod` | 하위 클래스에 필요한 인터페이스를 명시할 때 사용해요. |
| 믹스인 | 작고 재사용 가능한 기능을 클래스에 더하는 패턴이에요. |
| 합성 | 버스가 승객을 가지듯 다른 객체를 속성으로 보관해 협력해요. 상속 관계가 아닌 경우에 자연스럽습니다. |
| `Protocol` | 특정 부모를 상속했는지보다 필요한 구조와 메서드를 갖췄는지 표현하는 정적 타입 도구예요. |
| 상속의 주의점 | 부모 변경이 자식에 영향을 줄 수 있고, 깊은 계층은 상태와 호출 흐름을 추적하기 어렵게 해요. |

일반 속성 탐색을 인스턴스→클래스→부모로만 외우는 것도 단순화예요. 실제로는 프로퍼티 같은 데이터 디스크립터가 인스턴스 딕셔너리보다 우선할 수 있습니다.

## 5. 캡슐화는 값이 바뀌는 통로를 정리하는 일이에요

날짜를 `year`, `month`, `day`로 저장해도 아무 값이나 대입할 수 있다면 잘못된 일정이 만들어질 수 있어요. getter와 setter는 읽기와 변경의 통로를 만들고, 그 통로에서 유효성을 검사하도록 돕습니다.

`__year`처럼 앞에 밑줄 두 개를 쓰면 이름 맹글링이 적용돼 클래스 이름을 포함한 내부 이름으로 바뀌어요. 외부에서 `s1.__year = ...`를 실행하면 일반적인 인스턴스에서는 별개의 속성을 만들 뿐, 기존 내부 값은 바뀌지 않을 수 있습니다. 하지만 맹글링은 보안 장치나 완전한 접근 금지가 아니에요.

원문의 2월 날짜를 무조건 28일로 고치는 setter는 윤년과 다른 달, 0 이하의 날짜를 다루지 못합니다. 아래에서는 표준 라이브러리의 날짜 검증을 이용해 잘못된 변경을 거부하도록 보완했어요. `schedule`은 클래스 이름 관례에 맞춰 `Schedule`로 정리했습니다.

```python
from datetime import date


class Schedule:
    def __init__(self, year, month, day):
        self.set_date(year, month, day)

    def set_date(self, year, month, day):
        date(year, month, day)
        self.__year = year
        self.__month = month
        self.__day = day

    def get_year(self):
        return self.__year

    def get_month(self):
        return self.__month

    def get_day(self):
        return self.__day

    def set_year(self, year):
        self.set_date(year, self.__month, self.__day)

    def set_month(self, month):
        self.set_date(self.__year, month, self.__day)

    def set_day(self, day):
        self.set_date(self.__year, self.__month, day)

    def __str__(self):
        return f"year={self.__year}, month={self.__month}, day={self.__day}"


schedule = Schedule(2026, 8, 18)
schedule.set_month(2)
try:
    schedule.set_day(31)
except ValueError:
    print("유효하지 않은 날짜여서 기존 값을 유지합니다.")
print(schedule)
```

세 값을 검사한 뒤 함께 대입하므로 검증이 실패했을 때 일부만 변경되는 문제를 피할 수 있습니다. 여러 필드를 함께 바꾸려면 `set_date()`를 이용할 수 있어요.

## 6. 강의 밖 질문과 기록 범위

원문의 “변수 할당 시간?”이라는 질문은 의도가 확정되지 않아 실행 시간에 대한 답을 덧붙이지 않았어요. 초기화 시점을 묻는 것이라면, `__init__` 실행 중 `self.name = name` 같은 문장에 도달했을 때 속성이 설정된다고 이해할 수 있습니다.

중복된 예제와 출력 구분선은 합쳤고, 코드에 섞여 있던 실행 결과는 제거했습니다. 예제는 설명용이며 실제 실행 결과나 메모리 주소를 새로 만들지 않았어요. Python 코드의 검증 범위는 문법 검사이며, 동작 테스트는 수행하지 않았습니다.
