# 0810 자료구조와 리스트

데이터가 여러 개가 되면 값을 저장하는 것만으로는 부족해요. 순서대로 꺼낼지, 중복을 없앨지, 이름으로 찾을지에 따라 담는 방법이 달라집니다. 이번 기록에서는 자료구조의 차이를 살펴보고, 리스트에 데이터를 추가하고 수정하는 흐름을 정리해요.

## 1. 데이터를 어떤 기준으로 모을까요?

여러 데이터를 모아 다루는 대상을 컬렉션(collection)이라고 부릅니다. 원문에서 다룬 구분은 다음과 같아요.

| 자료구조 | 데이터를 다루는 기준 |
| --- | --- |
| 시퀀스 | 요소의 순서가 있고, 위치를 나타내는 인덱스로 접근해요. |
| 집합 `set` | 중복을 허용하지 않으며 위치에 따른 순서를 보장하지 않아요. |
| 사전 `dict` | 고유한 키와 그 키에 연결된 값의 쌍으로 저장해요. |

집합 A와 B의 합집합은 두 집합의 요소를 중복 없이 모은 것이에요. 사전에서는 키가 같으면 서로 다른 항목 두 개로 남지 않아요. 하나의 키에는 하나의 값 객체가 연결되지만, 그 값으로 리스트 같은 컬렉션을 넣을 수는 있어요. 서로 다른 키가 같은 값을 갖는 것도 가능합니다.

> 바로잡기: 사전의 키 하나에 여러 값이 직접 연결되는 것은 아니에요. 여러 값을 담은 컬렉션 하나를 값으로 연결한다고 설명하는 편이 정확합니다.

컬렉션을 다룰 때 자주 하는 일을 CRUD라고 묶어 부릅니다. 생성·추가(Create), 조회(Read), 수정(Update), 삭제(Delete)예요. SQL에서도 이런 데이터 조작을 많이 하지만, SQL 전체가 CRUD만으로 이루어진 것은 아니에요. 구조 정의나 권한 관리도 다룹니다.

## 2. 리스트에 값을 추가하는 방법

리스트는 변경 가능한 시퀀스예요. 대괄호 안에 요소를 나열하며, 기존 리스트에 값을 넣거나 지울 수 있습니다.

아래 코드는 원문의 예제를 정리한 학습용 코드예요. 출력 결과가 섞여 있던 구분선을 제거하고, `banna`를 `banana`로 고쳤습니다. 내장 타입 이름인 `list`를 변수명으로 덮어쓰지 않도록 `fruits`로 통일했어요.

```python
fruits = ["apple", "banana"]
fruits.append("watermelon")
fruits.insert(1, "pineapple")

add = ["cherry", "peach"]
fruits.extend(add)

combined = fruits + ["orange"]
```

`append(x)`는 요소 하나를 끝에 추가하고, `insert(index, x)`는 지정 위치에 요소를 넣어요. `extend(iterable)`는 반복 가능한 대상의 요소를 하나씩 가져와 추가합니다. 리스트와 튜플뿐 아니라 다른 이터러블도 받을 수 있어요.

이 세 메서드는 기존 리스트 객체를 바꿉니다. 반면 `+`는 두 리스트를 이어 붙인 새 리스트를 만들어요. 기존 객체가 바뀌는지, 새 결과를 변수에 받아야 하는지 구분하면 수정 결과를 놓치지 않을 수 있습니다.

> 바로잡기: 원문은 `extend(add)`를 두 번 호출하면서 한 번만 추가된 결과를 적었어요. 두 번 호출하면 같은 요소도 두 번 들어갑니다. 위 예제에서는 의도에 맞게 한 번만 호출했어요. 객체가 유지된다는 설명은 객체 정체성에 관한 것이며, 리스트 내부 저장 공간의 메모리 주소까지 고정된다는 뜻은 아니에요.

## 3. 조회한 위치에서 수정하고 삭제하기

```python
fruits = ["apple", "banana", "peach"]
second_fruit = fruits[1]
peach_index = fruits.index("peach")

fruits[1] = "cherry"
fruits.remove("peach")
fruits.clear()
```

인덱스는 0부터 시작하므로 `fruits[1]`은 두 번째 요소예요. `index(value)`는 값이 처음 나타나는 위치를 찾아줍니다. 찾은 위치에 `=`로 다른 값을 대입하면 해당 요소가 바뀌어요.

`remove(value)`는 처음 일치하는 요소를 지우고, `clear()`는 모든 요소를 지웁니다. `index()`와 `remove()`는 대상 값이 없으면 `ValueError`를 발생시켜요. 조회·삭제 전에 어떤 값이 들어 있는지 확인할 필요가 있는 이유입니다.
