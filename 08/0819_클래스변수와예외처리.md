## 1. 인스턴스마다 다른 값과 클래스가 공유하는 값

사용자의 이름은 사람마다 다르지만, 계산기가 호출된 횟수처럼 여러 객체가 함께 참조할 값도 있어요. 이 차이를 구분하는 것이 인스턴스 변수와 클래스 변수를 이해하는 출발점입니다.

일반적인 Python 객체에는 생성 후에도 속성을 붙일 수 있어요. 다만 필요한 속성을 `__init__`에 정리하면 객체의 초기 상태를 읽기 쉽습니다. `__slots__` 등으로 속성 추가가 제한되는 경우도 있으므로 모든 객체에 적용되는 규칙은 아니에요.

```python
class User:
    count = 0


user1 = User()
user2 = User()
user1.name = "김철수"
user1.age = 20
print(user1.name, user1.age)
print(user1.count, user2.count)

user1.count = 10
print(user1.count, user2.count, User.count)
```

처음에는 인스턴스에 `count`가 없어서 클래스의 값을 찾습니다. 하지만 `user1.count = 10`은 그 인스턴스에 같은 이름의 속성을 만들어 클래스 속성을 가려요. 클래스의 값을 바꾸려면 `User.count = ...`처럼 의도를 드러내면 됩니다. 공유 리스트처럼 변경 가능한 클래스 속성을 제자리에서 수정하는 경우는 별개의 주의가 필요해요.

> 정정: 원문의 `user1 = User`, `user2 = User`는 인스턴스 생성이 아니라 클래스 자체에 다른 이름을 붙이는 코드예요. 인스턴스를 만들려면 `User()`로 호출해야 합니다.

## 2. 메서드가 어떤 대상을 받는지 구분하기

인스턴스 메서드의 첫 인자 `self`는 인스턴스를 받지만, `@classmethod`의 첫 인자는 클래스예요. 보통 `cls`라고 부르며 원문의 `clz`도 문법상 가능한 이름입니다. `@staticmethod`는 인스턴스나 클래스를 자동으로 받지 않아요.

```python
class Calculator:
    count = 0

    @classmethod
    def add(cls, num1, num2):
        cls.count += 1
        print("호출 횟수:", cls.count)
        return num1 + num2

    @staticmethod
    def minus(num1, num2):
        return num1 - num2


print(Calculator.add(10, 20))
print(Calculator.minus(10, 20))
```

둘 다 인스턴스를 만들지 않고 호출할 수 있지만, 클래스 상태에 접근해야 하는지가 선택 기준이에요. 클래스 메서드는 상속받은 클래스에서 호출할 때 그 클래스를 전달받으므로 대체 생성자를 만들 때도 쓰입니다. 원문에 적힌 호출 횟수 `3`은 이전 실행이 누적된 상황일 수 있어요. 이 코드의 단 한 번 호출에 대한 검증 결과로 옮기지는 않았습니다.

원문의 클래스 개념 트리에 나온 관련 기능도 역할별로 묶어 두었어요.

| 기능 | 쓰임 |
| --- | --- |
| `@property` | 속성처럼 읽는 인터페이스에 getter와 setter 동작을 연결해요. |
| `__str__`, `__repr__` | 사용자용 표현과 개발자용 표현을 정의해요. |
| `__eq__`, `__lt__` | 비교 연산의 동작을 정의해요. |
| `__len__`, `__getitem__` | 길이 확인과 인덱싱 같은 컨테이너 동작을 제공해요. |
| `__call__` | 인스턴스를 함수처럼 호출할 수 있게 해요. |
| 상속, `super()`, MRO | 공통 기능 재사용과 메서드 탐색 순서를 연결해요. |
| `ABC`, `abstractmethod` | 구체 클래스가 구현할 동작을 명시해요. |
| 데이터 클래스 | 원문에 항목 이름만 남아 있어 세부 강의 내용은 확인할 수 없습니다. |

## 3. 실패를 예상해야 호출자가 대응할 수 있어요

문법이 맞는다고 모든 입력을 처리할 수 있는 것은 아니에요. 문자열을 정수로 바꾸거나 수를 나누는 작은 코드에서도 잘못된 입력이 들어올 수 있습니다. 예외 처리는 실패를 숨기는 기능이 아니라, 예상한 실패를 어디서 처리하고 어디로 전달할지 정하는 방법이에요.

`SyntaxError`는 코드를 해석할 때 발견되는 문법 문제입니다. 실행 중에는 다음과 같은 예외를 만날 수 있어요.

| 예외 | 대표 상황 |
| --- | --- |
| `IndexError` | 시퀀스에 없는 인덱스에 접근해요. |
| `ValueError` | 타입은 받을 수 있지만 값이 적절하지 않아요. `int("문자")` 같은 경우입니다. |
| `TypeError` | 연산이나 함수가 지원하지 않는 타입 또는 인자 형태를 전달해요. |
| `ZeroDivisionError` | 0으로 나누는 연산을 시도해요. |

논리 오류가 반드시 예외를 발생시키지는 않아요. 틀린 계산 결과를 정상적으로 반환할 수도 있으므로 테스트와 검토가 함께 필요합니다. 복구 불가능한 오류라면 계속 실행하는 것보다 실패를 알리고 안전하게 종료하는 편이 나을 수 있어요.

```python
try:
    num = int(input("0이 아닌 정수를 입력하세요: "))
    result = 10 / num
    print(result)
except ZeroDivisionError:
    print("0으로는 나눌 수 없습니다.")
except ValueError:
    print("정수 형식으로 입력해 주세요.")
else:
    print("정상 처리했습니다.")
finally:
    print("입력 처리 시도를 마쳤습니다.")
```

`try`에는 실패 가능성이 있는 작업을, `except`에는 해당 예외의 대안을 적어요. `else`는 `try`가 예외 없이 끝났을 때 실행하고, `finally`는 정상 종료나 예외 전파 과정에서 공통 정리를 맡습니다. 프로세스 강제 종료까지 보장하는 장치는 아닙니다. 파일 같은 자원은 `with`를 사용하는 편이 더 간단할 수 있어요.

같은 대안을 쓰는 예외는 `except (ZeroDivisionError, ValueError) as e:`처럼 묶을 수 있습니다. `except Exception as e:`를 추가할 때는 더 구체적인 예외 처리 뒤에 배치하고, 오류를 기록하거나 다시 발생시키는 등 책임 있는 처리가 필요해요.

> 정정: 모든 예외가 `Exception`의 자식인 것은 아닙니다. 최상위는 `BaseException`이고, `KeyboardInterrupt`, `SystemExit` 등은 `Exception`을 거치지 않아요. 원문의 인자 없는 `except:`는 이런 종료 신호까지 잡으므로 구체적인 예외를 지정하도록 고쳤습니다.

## 4. `raise`와 사용자 정의 예외로 실패의 의미 전달하기

함수 안에서 메시지만 출력하고 `return`하면 호출자는 무엇이 실패했는지 구별하기 어려울 수 있어요. `raise`는 예외 객체를 발생시켜 현재 정상 실행 흐름을 멈추고, 처리할 수 있는 호출자에게 실패를 전달합니다. 적절한 `except`가 있다면 프로그램 전체가 종료되는 것은 아니에요.

원문의 로그인 예제는 사용자 정의 예외를 구분하는 용도로 남기되, 고정 아이디와 평문 비밀번호 비교를 실제 인증 코드로 보이게 하지 않도록 수정했어요. 아래는 외부 인증 계층이 판정한 결과를 전달받는 설명용 함수입니다. 실제 인증 시스템은 포함하지 않습니다.

```python
class UserIdMismatchError(Exception):
    def __str__(self):
        return "아이디 확인에 실패했습니다."


class UserPassMismatchError(Exception):
    def __str__(self):
        return "비밀번호 확인에 실패했습니다."


def login(user_id_matches, user_pass_matches):
    if not user_id_matches:
        raise UserIdMismatchError()
    if not user_pass_matches:
        raise UserPassMismatchError()
    print("인증 성공 후 처리 위치입니다.")


try:
    login(user_id_matches=False, user_pass_matches=False)
except (UserIdMismatchError, UserPassMismatchError) as e:
    print(e)
```

`Exception`을 상속하고 `pass`만 둔 클래스도 예외로 사용할 수 있어요. 그때는 `raise UserIdMismatchError("설명")`처럼 메시지를 전달하면 됩니다. 위 코드는 원문의 다른 방식을 살려 `__str__`에서 메시지를 정의했어요. 예외별로 별도의 `except`를 작성하면 대응도 나눌 수 있습니다.

> 정정: 원문의 `if not(user_id != "...")`는 아이디가 일치할 때 예외를 발생시키는 반대 조건입니다. 불일치일 때 실패하도록 바로잡았습니다. 실제 서비스의 외부 응답에서는 아이디 존재 여부가 드러나지 않도록 인증 실패 메시지를 통일하는 편이 안전해요. 위 구분은 내부 처리 학습용입니다.

원문의 음수 나이 검증도 `raise`의 작은 예로 볼 수 있어요.

```python
def validate_age(age):
    if age < 0:
        raise ValueError("나이는 음수일 수 없습니다.")
    return age
```

이 예제는 `age`가 비교 가능한 수라는 전제이며, 타입이나 현실적인 연령 범위를 모두 검증하는 완성형 입력 검증기는 아닙니다.

## 5. traceback과 중단점으로 실패 위치 좁히기

예외가 생기면 traceback의 마지막 줄에서 예외 종류와 메시지를 먼저 확인하면 좋아요. 그 위의 파일 이름과 줄 번호를 따라가면 실패 지점과 호출 경로를 찾을 수 있습니다. traceback 자체는 보통 바깥 호출부터 안쪽 호출 순으로 표시되므로, “아래에서 위로 표시한다”보다는 “마지막 줄부터 읽어 원인을 좁힌다”가 정확해요.

VS Code나 노트북의 디버깅 기능에서는 중단점으로 실행을 멈추고 변수 값을 확인할 수 있어요. `Step Into`는 함수 내부로 들어가며 흐름을 추적하는 동작입니다. 이 노트에서 디버거를 실제 실행한 것은 아닙니다.

## 6. 자주 쓰는 함수로 값을 확인하기

`all()`과 `any()`는 요소의 진릿값을 모아 판단해요. `all()`은 모두 참인지, `any()`는 하나라도 참인지 확인합니다. 빈 iterable에서는 `all()`이 참, `any()`가 거짓이 됩니다. 빈 문자열과 달리 공백이 들어 있는 문자열은 참으로 평가해요.

```python
print(all([True, "a", " "]))
print(all([False, False]))
print(all([]))
print(any([False, 1, 0]))
print(any([]))
```

> 정정: 원문의 정의되지 않은 `a`는 문자열 `"a"`로 수정했어요. 함수 이름은 대문자 `All()`이 아니라 `all()`, `lens()`가 아니라 `len()`입니다.

길이와 합계를 확인한 뒤에는 수치를 어떻게 요약할지도 생각하게 됩니다. 평균은 극단값의 영향을 많이 받지만 중앙값은 정렬했을 때 가운데 위치를 기준으로 해요.

```python
import math
import statistics

nums = [1, 155, 20, 8, 7, 1000000]
print("개수:", len(nums))
print("합계:", sum(nums))
print("평균:", statistics.mean(nums))
print("중앙값:", statistics.median(nums))
print(round(10.56, 1))
print(math.ceil(10.2))
print(math.floor(10.56))
```

모듈 이름은 `statistic`이 아니라 `statistics`예요. `round()`는 내장 숫자에서 정확히 중간인 값을 가까운 짝수 쪽으로 반올림하며, 부동소수점 표현 때문에 직관과 다른 결과가 나올 수 있습니다. `math.floor()`는 음수에서도 아래쪽 정수를 택하므로 0 방향으로 소수부를 없애는 `int()`와 구별해야 해요.

원문에서 이름만 적힌 `map()`, `filter()`, `enumerate()`, `zip()`은 각각 변환, 조건 선택, 번호 붙이기, 여러 iterable 묶기에 해당합니다. 자세한 예제는 다음 날짜의 원문에 이어져 있어 이날 학습 결과처럼 추가하지 않았어요.

## 7. 과제와 기록 범위

원문 과제는 GitHub 저장소를 만들고 `README.md`에 메뉴별 실행 화면을 캡처해 정리하는 것이었습니다. 이는 해야 할 작업의 기록이며, 저장소 생성이나 업로드를 완료했다는 뜻은 아니에요. 자동 링크로 변환된 `readme.md`, `self.name`, `df.info` 같은 표기는 코드 이름으로 되돌렸습니다.

클래스 개념 트리의 끝부분은 제공된 원문 자체에 `[truncated]`로 잘려 있어 복원하지 않았습니다. 빈 탭과 반복 출력은 정리했고, 예제 속 고정 로그인 값은 제거했습니다. Python 예제는 문법 검사만 했으며, 입력 처리나 인증·디버깅을 실행해 검증하지는 않았습니다.
