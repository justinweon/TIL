# 0812 함수와 매개변수, 호출을 기록하는 메모리

같은 계산을 여러 번 사용하려면 처리 절차를 함수로 묶어두면 편해요. 함수에 어떤 값을 전달하고 무엇을 돌려받는지 이해한 뒤, 호출할 때 지역변수가 어디에서 유효한지까지 이어서 살펴봅니다.

## 1. 제어문 복습에서 함수 정의로

`if`는 조건이 참이면 해당 블록을 실행하고, 거짓이면 다음 `elif`나 `else`를 확인해요. 원문의 “참이면 넘어가고 거짓이면 걸린다”는 설명은 반대로 적혀 있어 바로잡았습니다. 여러 조건을 모두 만족해야 한다면 파이썬 키워드인 소문자 `and`를 사용해요.

`range(1, 10, 2)`는 1부터 시작해 10에 도달하기 전까지 2씩 증가하는 범위입니다. 인수가 하나일 때도 엄밀하게는 “반복 횟수”가 아니라 종료값이에요. 시작값 0과 간격 1이 기본으로 적용됩니다. 조건문과 반복문, 함수의 본문은 들여쓰기로 구분해요.

함수는 `def`로 정의합니다. 매개변수는 입력을 받을 이름, 함수 본문은 처리 절차, `return`은 호출한 곳에 돌려줄 값을 정해요. 원문의 레시피 비유처럼 재료를 받는 자리와 조리 절차를 구분하면 됩니다. 함수를 정의하는 것과 호출하는 것은 달라요. 정의만 해두면 일반적인 함수 본문은 아직 실행되지 않습니다.

```python
def calc(x):
    y = x * 2 + 1
    return y

result = calc(10)
calc2 = calc
another_result = calc2(20)
same_function = calc is calc2
```

`x`는 매개변수(parameter), 호출에 사용한 `10`은 인수(argument)예요. `calc2 = calc`는 계산 결과가 아니라 함수 객체 자체를 다른 이름으로 참조하게 합니다. 함수를 호출하려면 `calc2(20)`처럼 괄호를 붙여야 해요.

> 바로잡기: 원문의 함수 형식에서 바깥으로 빠진 `return`과 코드 안에 섞인 구분선·출력값을 정리했어요. `return`은 함수 본문 안에 있어야 합니다. 명시적으로 값을 반환하지 않은 함수는 `None`을 반환해요.

## 2. 위치, 이름, 기본값으로 인수 전달하기

```python
def add(num1, num2):
    return num1 + num2

positional = add(10, 20)
keyword = add(num2=20, num1=10)
mixed = add(10, num2=20)
```

위치 인수는 매개변수의 순서로 연결되고, 키워드 인수는 매개변수 이름으로 연결돼요. 일반적인 호출에서는 위치 인수를 먼저 쓰고 그다음 키워드 인수를 씁니다. 같은 매개변수에 값을 두 번 전달해서는 안 돼요.

> 바로잡기: `return = num1 + num2`는 문법 오류이며 `return num1 + num2`가 맞습니다. 임시 변수 `result`를 생략하는 주된 이유는 간결함이에요. 변수 하나를 줄였다는 사실만으로 의미 있는 메모리 절약이나 성능 향상을 단정할 수는 없습니다.

다음은 원문의 이름·연락처 예제를 익명화한 학습용 코드예요. 두 함수는 서로 다른 기본값 배치를 비교하기 위해 이름을 구분했습니다. 실제 연락처를 넣을 필요는 없어요.

```python
def add_with_contact(num1, num2, name, mobile="미입력"):
    return f"{num1 + num2}, {name=}, {mobile=}"

first = add_with_contact(10, 20, name="학습자")
second = add_with_contact(10, 20, mobile="예시 연락처", name="학습자")

def add_with_optional_name(num1, num2, mobile, name=None):
    return f"{num1 + num2}, {name=}, {mobile=}"

third = add_with_optional_name(10, 20, "예시 연락처")
```

기본값이 있는 매개변수는 그 인수를 생략했을 때 기본값을 사용해요. `None`도 기본값으로 쓸 수 있습니다. 원문에서 다룬 일반적인 위치·키워드 매개변수 목록에서는 기본값 없는 매개변수를 앞에 두어야 해요. 키워드로 전달한다고 해서 필수 매개변수가 선택 항목으로 바뀌는 것은 아닙니다.

## 3. 개수가 달라지는 인수 받기

원문의 `*nums` 예제는 여러 위치 인수를 하나의 튜플로 받는 방식이에요.

```python
def add(*nums):
    print(nums, type(nums))

add(10, 20)
add(10, 20, 30)
add(10, 20, 30, 40)
```

이 함수는 이름이 `add`이지만 합계를 계산하지 않고 인수와 타입을 표시해요. 기능은 함수 이름이 아니라 본문으로 결정됩니다. 인수를 넣지 않으면 `nums`는 빈 튜플이에요.

이름이 있는 인수를 가변적으로 받으려면 `**kwargs`를 사용합니다. 이것은 키와 값으로 이루어진 사전으로 모여요. `*nums`는 이름이 없어서 키워드를 “잃어버리는” 것이 아니라, 추가 위치 인수를 받도록 정의한 문법입니다. `**kwargs`는 추가 키워드 인수를 받는 별도 문법이에요.

## 4. 함수 객체와 호출 기록을 구분하기

함수 정의와 호출은 메모리를 설명할 때도 나누어 생각하면 좋아요. 이름 `calc`는 함수 객체를 참조하고, 호출하면 그 호출의 인수·지역변수·실행 위치를 관리하는 실행 문맥이 필요합니다. 서로 다른 호출은 각각의 지역 상태를 가질 수 있어요.

원문에 나온 `PyFunctionObject`, `PyCodeObject`, `PyFrameObject`는 CPython 구현을 이해할 때 사용하는 이름입니다. 함수 객체는 코드 객체와 전역 네임스페이스 등의 정보를 참조하고, 프레임은 호출의 실행 상태와 관련됩니다. 프레임의 지역 이름을 살펴보는 속성은 `f_locals`예요. 다만 실제 프레임의 구성과 객체 생성 시점은 CPython 버전에 따라 달라질 수 있습니다.

> 바로잡기: “전역변수는 모두 정적 메모리에 있고 영구히 제거되지 않는다”는 설명은 파이썬의 일반 규칙이 아니에요. 이름은 객체에 연결되는 바인딩이고, 모듈의 전역 이름도 바꾸거나 삭제할 수 있습니다. `int`와 `str`는 내장 타입이며 `print`는 제어문이 아니라 함수예요.

변수에 다른 값을 대입하면 이름이 다른 객체를 참조할 수 있어요. 대입할 때마다 새 객체가 반드시 생성되거나, GC가 “빈 주소”를 지운다고 이해하지는 않아야 합니다. CPython은 참조 계수와 순환 참조 수집 등을 사용하며, 더는 필요하지 않은 객체를 회수하는 방식과 시점은 구현에 영향을 받아요.

힙은 객체가 저장되는 메모리를 설명할 때, 콜 스택은 활성화된 호출의 순서를 설명할 때 자주 사용하는 용어입니다. 모든 지역 객체가 물리적인 스택 안에 직접 저장된다는 뜻은 아니에요. 함수가 반환되더라도 반환값, 클로저, 보관된 프레임 등에서 계속 참조하는 객체는 살아남을 수 있습니다.

## 5. 스택과 큐로 호출 순서 이해하기

스택은 나중에 넣은 것을 먼저 꺼내는 LIFO(Last In, First Out) 구조예요. 원문의 동전통처럼 위에서 넣고 위에서 꺼낸다고 생각하면 됩니다. 큐는 먼저 들어간 것을 먼저 꺼내는 FIFO(First In, First Out) 구조로, 대기열에 가깝습니다.

다음 코드는 원문의 중첩 호출 예제에서 출력과 구분선을 분리한 것입니다.

```python
def add(num1, num2):
    num3 = 30
    result = num1 + num2 + num3
    return result

def func(num):
    result = add(10, 20)
    result += num
    return result

result = add(10, 20)
combined_result = func(40)
```

모듈 수준의 `result`와 `add()` 내부의 `result`는 이름만 같고 바인딩되는 범위가 달라요. 매개변수도 지역 이름입니다.

`func(40)`을 호출하면 `func`가 먼저 실행되고, 그 안에서 `add`를 호출해요. `func`는 `add`가 반환할 때까지 기다립니다. 나중에 호출한 `add`가 먼저 반환하고 그다음 `func`가 작업을 마치므로 호출 흐름이 스택과 연결되는 거예요. 여기서 `add`는 `func` 내부에 정의된 함수가 아니라, 외부에 정의되어 `func`에서 호출하는 함수입니다.

## 6. 컴파일과 인터프리터를 너무 나누지 않기

컴파일은 코드를 다른 표현으로 변환하는 과정이고, 인터프리터는 코드를 해석·실행하는 방식이에요. 원문은 실행 전에 모두 번역하는 방식과 실행 중 해석하는 방식을 대비했지만, 두 방식은 함께 사용될 수 있습니다.

> 바로잡기: CPython도 소스 코드를 바이트코드로 컴파일한 뒤 실행합니다. “파이썬은 컴파일 없이 소스를 한 줄씩 바로 실행한다”는 설명은 부정확해요. JavaScript 구현도 JIT 컴파일 등을 사용할 수 있습니다. 컴파일 여부만으로 함수가 정적 메모리 또는 힙에 저장되는 위치를 단정할 수도 없어요.

파이썬에서 함수가 객체이고 다른 이름에 대입될 수 있다는 점은 이후 고차함수와 클로저를 이해하는 데 이어집니다. 그것이 인터프리터 언어만의 특성인 것은 아닙니다.

## 7. 기록 범위와 출처

제어문 복습, 함수 정의·호출·반환, 매개변수와 인수, 위치·키워드·기본값·가변 인수, 함수 별칭, 메모리와 지역·전역 이름, 스택·큐·콜 스택, 컴파일·인터프리터 비교를 반영했어요. 반복된 `calc`와 `add` 코드는 개념별 예제로 합쳤습니다. 출력값과 메모리 주소는 실행 증거로 옮기지 않았어요.

예제는 원문을 고친 학습용 코드이며 문법 검사 대상입니다. 문서 생성 과정에서 함수의 실행 결과나 성능을 측정한 것은 아니에요.
