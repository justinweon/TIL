# 0813 스코프에서 콜백, 클로저와 데코레이터까지

함수에 숫자 대신 함수를 전달하면 처리 방식을 바꿔 끼울 수 있어요. 함수를 반환하면 특정 설정을 기억하는 새 함수도 만들 수 있습니다. 이런 사용법을 이해하려면 먼저 함수 안의 이름이 어디까지 보이는지 알아야 해요.

## 1. 함수 본문과 반환을 다시 확인하기

`*args`는 추가 위치 인수를 튜플로, `**kwargs`는 추가 키워드 인수를 사전으로 모아요. 인수가 없으면 각각 빈 튜플과 빈 사전입니다. 원문의 “비어 있으면 값은 0”이라는 설명은 일반 규칙이 아니에요. `sum(args)`를 반환하도록 작성했다면 빈 입력의 합이 0이지만, 인수 수집 자체가 0을 반환하지는 않습니다.

```python
def add():
    pass
```

`pass`는 아무 작업도 하지 않는 문장입니다. 함수나 조건문의 본문을 아직 작성하지 않았을 때 문법적으로 빈 블록이 되지 않게 사용할 수 있어요. 위 함수는 호출하면 `None`을 반환합니다. 원문에 섞인 `incompleteInputError`는 이 코드의 실행 결과가 아니며, 빈 블록의 정확한 오류 표시는 입력 환경에 따라 달라질 수 있어요.

`return`은 현재 함수의 실행을 끝내고 값을 돌려줍니다. 일반적인 위치·키워드 매개변수에서는 기본값 없는 항목을 먼저, 기본값 있는 항목을 뒤에 놓아요.

## 2. 이름을 찾는 범위: LEGB

스코프(scope)는 이름에 접근할 수 있는 범위입니다. 함수의 매개변수와 내부에서 정의한 이름은 지역 이름이고, 모듈 수준에서 정의한 이름은 전역 이름이에요.

```python
a = 10

def func():
    b = 20
    return b

local_value = func()
print(a, local_value)
```

원문은 함수 밖에서 `print(a, b)`를 실행하려 했어요. `b`는 함수 내부의 이름이므로 밖에서 직접 찾을 수 없습니다. `func()`를 한 번 호출한다고 해서 `b`가 전역 이름이 되는 것도 아니에요. 위처럼 반환값을 받으면 내부 결과를 외부에서 사용할 수 있습니다.

일반적인 함수 안에서 이름을 찾는 순서는 LEGB입니다.

| 단계 | 찾는 곳 |
| --- | --- |
| Local | 현재 함수의 지역 범위 |
| Enclosing | 바깥쪽 함수의 범위 |
| Global | 현재 모듈의 전역 범위 |
| Built-in | 내장 이름 공간 |

`Global`은 “전역함수”라는 뜻이 아니고, `Built-in`에도 함수뿐 아니라 타입·예외 등의 이름이 있어요. 안쪽 함수는 바깥쪽 함수의 이름을 읽을 수 있지만, 바깥쪽 함수가 안쪽 함수의 지역 이름을 직접 읽을 수는 없습니다.

```python
a = "전역"

def outer():
    a = "바깥 함수"
    print("outer:", a)

    def inner():
        a = "지역"
        print("inner:", a)

    inner()

outer()
```

같은 이름이라도 가까운 범위의 이름이 먼저 선택됩니다. 전역 이름을 대상으로 하겠다고 선언하려면 `global`을 사용해요.

```python
a = "전역"

def outer():
    a = "바깥 함수"
    print("outer:", a)

    def inner():
        global a
        print("inner:", a)

    inner()

outer()
```

`global a`는 현재 함수에서 `a`의 바인딩을 모듈 전역 이름으로 취급하겠다는 선언입니다. 단순히 전역 값을 읽을 때는 보통 선언이 필요 없지만, 위처럼 중간 범위의 같은 이름을 건너뛰거나 전역 이름을 재대입할 때 의미가 있어요.

## 3. 함수를 인수로 전달하는 콜백

파이썬의 함수는 일급 객체예요. 변수에 대입하거나, 인수로 전달하거나, 다른 함수의 반환값으로 사용할 수 있습니다. “함수와 변수가 같다”기보다는 함수 객체도 다른 값처럼 취급할 수 있다고 이해하면 정확해요. 원문의 로마 시민권 비유는 기술적 정의와 무관하고 역사적 설명도 확인되지 않아 옮기지 않았습니다. 일급 함수는 인터프리터 언어만의 기능도 아니에요.

콜백은 다른 코드에 전달되어 그 코드가 필요할 때 호출하는 함수입니다.

```python
def callback():
    print("콜백 실행")

def func(a):
    print("func 실행")
    a()

func(callback)
```

`func(callback)`은 함수 자체를 전달합니다. `func(callback())`처럼 쓰면 먼저 `callback()`을 실행한 반환값을 전달하게 되므로 의미가 달라져요.

원문의 숫자 변환 예제는 콜백만 바꿔 같은 반복 구조를 재사용합니다.

```python
def change_numbers(*args, callback):
    numbers = list(args)
    for i in range(len(numbers)):
        numbers[i] = callback(numbers[i])
    return numbers

def square(num):
    return num ** 2

def plus(num):
    return num + 10

squared = change_numbers(10, 20, 30, callback=square)
increased = change_numbers(10, 20, 30, callback=plus)
```

> 바로잡기: `change_nunmbers`와 `squre`를 각각 `change_numbers`, `square`로 통일하고, `for` 뒤의 콜론을 보완했어요. `return numbers`는 반복문 밖에 둬야 모든 요소를 처리합니다. `callback`은 `*args` 뒤에 있으므로 키워드로 전달해야 해요.

### 주문 알림으로 다시 연결하기

원문 개인 연습에는 주문 처리는 그대로 두고 문자·이메일 알림 함수를 바꾸는 예제가 있어요. 그 의도를 유지하고 화면 문구만 한국어로 정리했습니다.

```python
def send_sms(message):
    print(f"문자 알림: {message}")

def send_email(message):
    print(f"이메일 알림: {message}")

def process_order(item, callback):
    print(f"{item} 주문을 처리합니다.")
    callback(f"{item} 배송이 시작되었습니다.")

process_order("치킨", send_sms)
process_order("소고기", send_email)
```

`process_order`는 전달받은 함수가 문자인지 이메일인지 판단하지 않고 호출해요. 이렇게 주문 처리와 알림 방식을 분리하면 알림 기능을 바꿀 때 주문 처리 본문을 고치지 않아도 됩니다.

> 바로잡기: 이 코드는 `print()`로 문구만 표시하는 연습이에요. 실제 주문을 처리하거나 문자·이메일을 발송하지 않습니다. 원문의 “발송된다”는 표현은 예제 범위에 맞춰 고쳤어요.

## 4. 람다와 `map()`, `filter()`

`lambda 매개변수: 표현식`은 표현식 하나의 결과를 반환하는 함수를 만듭니다. 짧은 콜백에 쓰기 편하지만 반드시 일회용일 필요는 없고, 매개변수를 한 글자로 지어야 한다는 규칙도 없어요. 오래 재사용하거나 로직이 길어지면 `def`로 이름을 붙이는 편이 읽기 좋습니다.

```python
square = lambda num: num ** 2
value = square(1)

# 앞 절에서 정의한 change_numbers가 필요해요.
squared = change_numbers(10, 20, 30, callback=lambda num: num ** 2)

fruits = ["apples", "orange", "mango"]
decorated = list(map(lambda x: f"**{x}**", fruits))

numbers = [*range(1, 11)]
odd_numbers = list(filter(lambda x: x % 2 == 1, numbers))
filter_object = filter(lambda x: x >= 70, [50, 80, 40, 90])
```

`map()`은 각 요소를 변환하고, `filter()`는 조건의 결과가 참인 요소를 남겨요. 둘 다 이터레이터를 반환하므로 위에서는 결과를 모아 보기 위해 `list()`를 사용했습니다. 반드시 람다를 넣어야 하는 것은 아니며 일반 함수도 받을 수 있어요.

원문의 `change_numbers(lambda x: x**2, 10, 20, 30)`은 앞서 정의한 함수의 매개변수 구조와 맞지 않아 `callback=` 호출로 고쳤습니다.

## 5. 바깥 값을 기억하는 클로저와 함수 팩토리

함수를 인수로 받거나 함수를 반환하는 함수를 고차함수라고 부릅니다. 그중 설정에 맞는 새 함수를 만들어 반환하는 패턴을 함수 팩토리로 볼 수 있어요. 원문에 섞인 “팩토리얼 함수”와는 다른 개념입니다.

```python
def outer(num1):
    def inner(num2):
        return num1 + num2
    return inner

a = outer(10)
b = outer(20)
first = a(20)
second = b(20)
```

`outer(10)`이 반환한 것은 `inner` 함수입니다. 이후 `a(20)`을 호출하면 내부 함수가 바깥의 `num1`에 계속 접근할 수 있어요. 이런 식으로 자유 변수에 대한 바인딩을 유지하는 함수를 클로저라고 설명합니다.

> 바로잡기: 바깥 함수가 내부 함수를 기억하는 것이 아니라, 내부 함수가 자신이 사용하는 바깥 범위의 바인딩을 유지해요. CPython에서는 이런 바인딩을 셀 객체(`PyCellObject`)로 설명할 수 있습니다. 함수 종료 후 모든 지역 객체가 무조건 사라졌다가 힙으로 이동하는 것은 아니에요. 참조가 유지되는 값은 계속 살아남을 수 있습니다.

원문에는 바깥에서 정한 값과 안쪽에서 정한 값을 더해 출력하는 형태도 있어요.

```python
def outer():
    num1 = 10
    def inner():
        num2 = 20
        print(num1 + num2)
    return inner

inner = outer()
inner()
```

이 구조를 여러 단계로 만들면 앞 단계의 인수를 고정해둘 수 있습니다.

```python
def add(num1):
    def _add(num2):
        def __add(num3):
            return num1 + num2 + num3
        return __add
    return _add

result1 = add(10)(20)(30)
add10 = add(10)
result2 = add10(30)(40)
add10_20 = add(10)(20)
result3 = add10_20(40)
```

클로저가 반드시 여러 단계여야 하는 것은 아니에요. 이 예제는 단계별로 값을 고정하는 사용법을 보여줍니다.

## 6. 공통 처리를 감싸는 데코레이터

원문은 반복해서 쓰는 문제 해결 구조를 디자인 패턴에 비유하고, 함수 실행 전후의 공통 기능을 감싸는 데코레이터를 소개합니다. 파이썬의 `@` 문법은 함수를 다른 호출 가능 객체에 전달한 결과로 이름을 다시 연결하는 데 사용할 수 있어요.

```python
def my_decorator(func):
    def wrapper():
        print("함수 실행 전")
        func()
        print("함수 실행 후")
    return wrapper

@my_decorator
def say_hello():
    print("안녕하세요.")

say_hello()
```

위 예제에서 `@my_decorator`는 정의한 함수에 `say_hello = my_decorator(say_hello)`를 적용하는 의미입니다. 이 단순한 `wrapper()`는 인수와 반환값을 전달하지 않으므로 인수 없는 알림 예제에 한정돼요.

### 반복과 재귀로 팩토리얼 계산하기

팩토리얼은 `5!`처럼 숫자 뒤에 느낌표를 쓰며, 양의 정수를 차례로 곱하는 연산입니다. `0!`은 1이에요. 원문의 반복·재귀 두 방법을 보존하고, 음수나 비정수 입력을 잘못 받아들이지 않도록 검사를 보완했습니다.

```python
def factorial1(num):
    if type(num) is not int or num < 0:
        raise ValueError("0 이상의 정수가 필요합니다.")
    result = 1
    for i in range(1, num + 1):
        result *= i
    return result

def factorial2(num):
    if type(num) is not int or num < 0:
        raise ValueError("0 이상의 정수가 필요합니다.")
    if num < 1:
        return 1
    return num * factorial2(num - 1)
```

재귀는 함수가 자신을 다시 호출하는 방식이에요. 종료 조건이 필요하고, 일반적인 CPython 실행에서는 재귀 호출이 깊어질수록 호출 기록이 쌓이며 재귀 깊이 제한에도 걸릴 수 있습니다. 반복 방식은 이 호출 부담을 피할 수 있어요. 다만 “반복이 언제나 빠르다”거나 “재귀가 늘 읽기 좋다”고 일반화하지는 않아야 합니다. 여기서는 성능을 측정하지 않았어요.

### 시간 측정 코드를 공통 기능으로 분리하기

원문은 직접 시간을 재는 코드에서 콜백 함수, 데코레이터 순서로 확장합니다. 아래는 앞의 `factorial2` 정의가 필요한 예시예요. 경과 시간에는 시스템 시각용 `time.time()` 대신 `time.perf_counter()`를 사용하도록 보완했습니다.

```python
import time

start = time.perf_counter()
result = factorial2(10)
end = time.perf_counter()
print(result)
print("걸린 시간:", end - start)

def time_checker(callback, num):
    start = time.perf_counter()
    result = callback(num)
    end = time.perf_counter()
    print("걸린 시간:", end - start)
    return result

result = time_checker(factorial2, 10)
```

공통 처리를 반환 함수로 감싸면 호출할 때마다 측정 코드를 다시 쓰지 않아도 돼요. 원문의 `time_check2`를 여러 인수와 키워드 인수를 전달할 수 있도록 정리한 예시입니다. 함수 정보 보존을 위한 `functools.wraps`는 보완 사항이에요.

```python
import time
from functools import wraps

def time_check2(callback):
    @wraps(callback)
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = callback(*args, **kwargs)
        end = time.perf_counter()
        print("걸린 시간:", end - start)
        return result
    return wrapper

@time_check2
def add(num1, num2):
    return num1 + num2

result = add(10, num2=20)

# 앞의 factorial2 정의가 필요하며, 최상위 호출을 감싸는 예시예요.
timed_factorial = time_check2(factorial2)
factorial_result = timed_factorial(10)
```

> 바로잡기: 원문의 조기 `return result` 뒤에 있던 시간 측정은 실행될 수 없어 반환을 마지막으로 옮겼어요. `return1`도 `return 1`로 수정했습니다. 정의에서 `*args`·`**kwargs`는 인수를 모으고, 호출에서 `callback(*args, **kwargs)`는 다시 풀어 전달합니다.

재귀 함수 이름 자체에 `@time_check2`를 적용하면 재귀 단계마다 감싼 함수가 다시 호출되어 측정이 중첩될 수 있어요. 위에서는 원래 이름을 유지하고 별도의 `timed_factorial`로 감싸 최상위 호출을 측정하는 형태를 보였습니다. 예외가 발생하면 위 래퍼의 시간 출력 부분까지 도달하지 않는다는 제한도 있어요. 실제 측정값은 이 문서에 넣지 않았습니다.

## 7. 개인 연습에서 남은 질문: `sum(a, b)`가 안 되는 이유

원문의 계산기 연습은 연산 함수를 전달해 같은 호출 흐름을 재사용하는 예제입니다.

```python
def add(a, b):
    return a + b

def multiply(a, b):
    return a * b

def calculate(a, b, callback):
    result = callback(a, b)
    print(f"결과: {result}")

calculate(10, 5, add)
calculate(10, 5, multiply)
```

`sum(iterable, start=0)`은 반복 가능한 첫 번째 인수의 요소를 시작값에 더합니다. `sum(10, 5)`는 첫 번째 인수 `10`을 순회할 수 없어 `TypeError`가 발생해요. 두 번째 인수 `5`는 두 번째 피연산자가 아니라 시작값입니다. 파이썬이 의도를 오해하는 것이 아니라 정의된 규칙을 적용한 결과예요.

두 수를 더할 때는 `a + b`가 의도를 바로 드러내고, 여러 값을 모아 더할 때는 `sum([a, b])`처럼 사용할 수 있어요. 원문의 속도 우열은 측정 근거가 없으므로 일반적인 성능 결론으로 옮기지 않았습니다.
