# TIL: LangChain 기초와 LLM 애플리케이션

오늘은 LLM 애플리케이션에서 질문이 답변으로 이어지는 과정을 정리해 보았습니다. 전통적 소프트웨어와 무엇이 다른지부터 살펴보고, LangChain으로 입력을 준비한 뒤 Ollama 모델을 호출하고 응답을 문자열로 꺼내 봅니다. 각 구성 요소가 왜 필요한지 이해한 다음 하나의 체인으로 연결하는 것이 이번 학습의 목표입니다.

## 1. 전통적 소프트웨어와 LLM 애플리케이션

LLM 애플리케이션을 만들기 전에, 프로그램에 언어 모델이 들어오면 무엇이 달라지는지 생각해 보면 좋겠습니다. 전통적 소프트웨어에서는 주로 개발자가 조건문, 알고리즘, DB 쿼리로 처리 규칙을 직접 작성합니다. 프로그램은 이 규칙에 따라 입력을 처리하죠. 그렇다고 결과가 항상 고정된 것은 아닙니다. 입력이나 데이터베이스 상태에 따라 결과는 달라질 수 있습니다.

반면에 LLM 애플리케이션은 어떨까요? LLM 애플리케이션은 학습된 언어 모델로 자연어 입력과 문맥을 해석하고 답변을 생성합니다. 같은 질문을 여러 방식으로 표현해도 더 유연하게 대응할 수 있는 것이죠. 다만 그럴듯하게 들리는 답변이 반드시 정확한 답변인 것은 아닙니다.

두 방식을 함께 사용할 수도 있습니다. 사용자가 ‘내 택배 어디쯤 왔어?’라고 묻는 상황을 생각해 볼까요? DB 쿼리는 주문 상태를 조회하고, LLM은 질문을 해석해 조회 결과를 자연어로 설명할 수 있습니다. 그래서 LLM의 입력과 출력을 배우는 것입니다. 자연어를 처리하는 단계가 전체 프로그램에서 어떻게 연결되는지 알아야 하니까요.

## 2. LLM의 입력·출력과 LangChain

언어 모델을 애플리케이션에 연결하려면 무엇을 보내고 무엇을 돌려받는지 알아야 합니다. 가장 기본적인 흐름은 다음과 같습니다.

```text
입력(프롬프트 또는 메시지) -> 언어 모델 -> 출력(응답)
```

LangChain은 언어 모델 기반 애플리케이션을 만드는 프레임워크입니다. 프롬프트 템플릿과 출력 파서처럼 모델 주변에 필요한 구성 요소를 연결할 수 있게 도와줍니다. 아래 예제에서는 질문을 준비하고, 모델에 보낸 뒤, 응답에서 텍스트를 꺼내 봅니다. 각 단계를 먼저 나누어 이해하면 마지막에 하나로 연결하는 과정도 따라가기 쉽습니다.

## 3. 의존성 설치

이 흐름을 코드로 작성하려면 먼저 필요한 패키지를 준비해야 합니다. 프로젝트 터미널에서 아래 명령어로 추가할 수 있습니다. 각 패키지가 어디에 쓰이는지는 표에 정리했습니다.

```bash
uv add langchain langchain-core langchain-ollama python-dotenv ipykernel
```

| 패키지 | 용도 |
|---|---|
| `langchain` | 언어 모델 기반 애플리케이션 개발 프레임워크 |
| `langchain-core` | 프롬프트, 메시지, 실행 가능한 구성 요소의 기본 인터페이스 |
| `langchain-ollama` | LangChain과 Ollama 연동 |
| `python-dotenv` | `.env` 파일의 변수를 실행 환경에 불러오기 |
| `ipykernel` | Python 환경을 Jupyter 노트북 커널로 사용하기 |

`uv add`를 사용하면 의존성이 `pyproject.toml`에 기록되고, 일반적으로 잠금 파일과 프로젝트 환경도 함께 업데이트됩니다. 처음 메모에서 패키지 이름에 오타가 있었는데요. `landchaing-ollama`가 아니라 `langchain-ollama`가 맞습니다.

여기서 연동 패키지와 모델 서버의 역할은 구분해야 합니다. `langchain-ollama`를 설치하면 Python에서 사용할 연동 기능이 준비되지만, Ollama 서버가 설치되거나 모델이 다운로드되는 것은 아닙니다. 예제를 실행하려면 Ollama 서버가 실행 중이고 `mistral` 모델도 준비되어 있어야 합니다. GitHub에 프로젝트를 저장할 때는 인증 정보나 비밀 값이 담긴 `.env` 파일을 커밋하지 않도록 주의합니다.

## 4. 프롬프트 엔지니어링

도구를 준비했으니 이제 모델에게 무엇을 부탁할지 생각해 보겠습니다. 단순히 ‘CPU를 설명해 주세요’라고 하면 대상 독자나 설명 길이, 말투가 정해져 있지 않습니다. ‘초보자에게 일상적인 비유로 설명해 주세요’라고 하면 방향이 조금 더 분명해지죠. 이렇게 목표, 제약 조건, 출력 형식을 설계하는 과정을 프롬프트 엔지니어링이라고 합니다.

| 요소 | 목적 | 예시 |
|---|---|---|
| 목표 | 수행할 작업 지정 | 초보자에게 CPU의 역할을 설명하세요. |
| 제약 조건 | 범위, 말투, 길이 지정 | 일상적인 사물에 비유하고 두 문장 이내로 설명하세요. |
| 출력 형식 | 일관된 구조 유도 | ‘정의:’와 ‘비유:’로 시작하는 두 줄로 작성하세요. |

이러한 지침은 원하는 응답을 유도하지만, 모델이 모든 조건을 지킨다고 보장하지는 않습니다. 애플리케이션에서 정확한 형식이 필요하다면 구조화된 출력이나 검증 같은 장치도 함께 사용해야 합니다. 지침을 코드로 옮기기 전에 이 차이를 기억해 두면 좋겠습니다.

## 5. 메시지 역할과 프롬프트 템플릿

채팅 프롬프트에서는 전반적인 지침과 사용자의 질문을 서로 다른 역할로 구분합니다. 각각을 역할과 내용이 있는 메시지로 표현하고, 대화 순서대로 리스트에 담을 수 있습니다.

| 역할 | LangChain 클래스 | 용도 |
|---|---|---|
| `system` | `SystemMessage` | 역할, 상황, 말투, 제약 조건 등의 전반적인 지침 |
| `user` | `HumanMessage` | 사용자의 질문이나 요청 |
| `assistant` | `AIMessage` | AI 응답 또는 대화 기록에 포함된 이전 AI 응답 |

전반적인 지침은 시스템 메시지에 넣는 경우가 많지만, 상황과 제약 조건, 예시를 모두 그곳에 넣어야 하는 것은 아닙니다. 예를 들어 대화 예시는 사용자 메시지와 AI 메시지 쌍으로 보여줄 수도 있습니다. 첫 템플릿에서는 시스템 지침 하나와 사용자 질문 하나로 간단하게 구성해 보겠습니다.

```python
from langchain_core.prompts import ChatPromptTemplate

# (역할, 내용) 튜플의 리스트로 템플릿 구성
prompt_template = ChatPromptTemplate.from_messages([
    (
        "system",
        "당신은 컴퓨터 기초 개념을 일상적인 사물에 빗대어 설명하는 "
        "교육 전문가입니다. 2문장 이내로 친절하게 설명하세요."
    ),
    ("user", "{user_question}")
])

# 자리표시자에 실제 질문 채우기
prompt_value = prompt_template.invoke({
    "user_question": "CPU가 무엇인가요?"
})

messages = prompt_value.to_messages()
```

`{user_question}`은 다음 질문을 넣기 위해 비워 둔 자리라고 생각하면 됩니다. 템플릿의 `.invoke()`를 호출하면 이 자리가 채워지고 `ChatPromptValue`가 만들어집니다. 이어서 `.to_messages()`를 호출하면 메시지 리스트를 얻을 수 있고, 이 예제에는 시스템 메시지와 사용자 메시지가 들어 있습니다. 여기까지는 입력을 준비한 단계입니다. 아직 모델을 호출하거나 AI 답변을 생성한 것은 아닙니다.

출력 지침을 더 구체적으로 작성할 수도 있습니다. 아래 버전에서는 정의와 비유를 각각 한 줄로 요청합니다. 앞서 배운 프롬프트 엔지니어링의 출력 형식을 적용한 예입니다.

```python
formatted_prompt_template = ChatPromptTemplate.from_messages([
    (
        "system",
        "당신은 초보자에게 컴퓨터 기초 개념을 설명하는 교육 전문가입니다. "
        "일상적인 사물에 비유하고, 친절하게 설명하세요. "
        "출력은 정확히 두 줄로 작성하세요: "
        "첫 줄은 '정의:'로 시작하는 한 문장, "
        "둘째 줄은 '비유:'로 시작하는 한 문장입니다."
    ),
    ("user", "{user_question}")
])
```

## 6. 모델 인스턴스 생성

프롬프트는 준비되었지만, 답변을 만들어 줄 모델은 아직 연결하지 않았습니다. `ChatOllama`를 사용해 Ollama 서버의 `mistral` 모델과 통신하도록 설정합니다.

```python
from langchain_ollama import ChatOllama

model = ChatOllama(
    model="mistral",
    base_url="http://localhost:11434/"  # Ollama 서버 주소
)
```

`ChatOllama(...)`는 Ollama와 통신할 객체를 만들고, `model="mistral"`은 사용할 모델 이름을 지정합니다. `base_url`은 서버가 어디에 있는지 알려 주는 주소입니다. 여기서 `localhost`는 이 Python 코드가 실행되는 환경 자신을 가리킵니다. 주소에는 붙여넣기 과정의 `@url:` 표기나 백틱을 빼고 URL만 넣어야 합니다.

인스턴스를 만드는 것은 이렇게 연결 설정을 준비하는 단계입니다. 모델을 새로 학습하거나 답변을 생성하지는 않습니다. 앞에서 준비한 프롬프트로 답변을 받으려면 실제로 모델을 호출해야 합니다.

```python
response = model.invoke(prompt_value)
print(response.content)
```

두 단계 모두 `.invoke()`라는 이름을 사용하지만 하는 일은 다릅니다. `prompt_template.invoke()`는 템플릿을 채우고, `model.invoke()`는 준비된 입력을 모델에 보내 `AIMessage`를 받습니다. 예제에서는 `.content`로 응답 내용을 출력합니다.

## 7. StrOutputParser로 텍스트 추출

모델에서 받은 결과는 `AIMessage`입니다. 다음 작업에 답변 텍스트만 필요하다면, 메시지 객체를 그대로 넘기는 대신 출력 파서로 문자열을 꺼낼 수 있습니다.

```python
from langchain_core.output_parsers import StrOutputParser

parser = StrOutputParser()

# 모델 응답에서 텍스트를 Python 문자열로 추출
text = parser.invoke(response)
print(text)
```

모델 객체를 만드는 것만으로 답변이 생기지 않았던 것처럼, 파서도 생성만 해서는 응답을 처리하지 않습니다. `parser.invoke(response)`에 응답을 전달해야 실제 작업이 이루어집니다. 이 텍스트 응답 흐름에서는 `AIMessage`의 텍스트를 꺼내 Python `str`로 반환합니다.

여기서 말하는 ‘순수 텍스트’에는 작은 구분이 필요합니다. 메시지 객체 대신 문자열을 받는다는 뜻이지, Markdown 서식을 자동으로 없앤다는 뜻은 아닙니다. 앞에서 요청한 두 줄 형식을 지켰는지 검사해 주는 것도 아닙니다.

## 8. LCEL로 흐름 연결

지금까지는 프롬프트를 채우고, 모델을 호출하고, 응답을 파서에 전달하는 작업을 따로 실행했습니다. LCEL, 즉 **LangChain Expression Language**를 사용하면 이 순서를 하나의 체인으로 연결할 수 있습니다. `|` 연산자는 앞 구성 요소의 출력을 다음 구성 요소의 입력으로 넘겨줍니다.

```python
chain = prompt_template | model | parser

answer = chain.invoke({
    "user_question": "CPU가 무엇인가요?"
})

print(answer)
```

| 단계 | 동작 | 출력 |
|---|---|---|
| `prompt_template` | 질문 자리표시자 채우기 | `ChatPromptValue` |
| `model` | 모델 응답 생성 | `AIMessage` |
| `parser` | 응답 텍스트 추출 | `str` |

```text
질문 딕셔너리 -> 프롬프트 -> 모델 -> 출력 파서 -> 문자열
```

체인이 따르는 순서는 앞에서 실행한 것과 같습니다. 이제 각 구성 요소를 따로 호출하지 않아도 되는 것이죠. `chain = ...`은 흐름을 구성하고, `chain.invoke(...)`는 그 흐름을 실행합니다. 마지막으로 파서가 반환한 문자열을 받게 됩니다.

### 전체 예제

각 구성 요소의 역할을 살펴보았으니, import부터 설정과 체인 호출까지 한곳에 모아 보겠습니다.

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_ollama import ChatOllama

# 1. 지침과 질문 자리표시자 정의
prompt_template = ChatPromptTemplate.from_messages([
    (
        "system",
        "당신은 컴퓨터 기초 개념을 일상적인 사물에 빗대어 설명하는 "
        "교육 전문가입니다. 2문장 이내로 친절하게 설명하세요."
    ),
    ("user", "{user_question}")
])

# 2. Ollama 모델 연결 설정
model = ChatOllama(
    model="mistral",
    base_url="http://localhost:11434/"
)

# 3. 문자열을 반환하는 파서 생성
parser = StrOutputParser()

# 4. 구성 요소 연결 및 체인 실행
chain = prompt_template | model | parser
answer = chain.invoke({"user_question": "CPU가 무엇인가요?"})

print(answer)
```

이 전체 예제는 강의 코드와 이해를 위한 보충 내용을 한곳에 모은 것입니다. 실행하려면 앞에서 설명한 패키지, Ollama 서버, 모델이 필요합니다. 이 노트에는 실제 모델 실행 결과를 담지 않았습니다.

답변을 확인할 때 쓸 수 있는 작은 팁도 있습니다. Python 기본 제공 모듈인 `pprint`를 사용하면 출력을 조금 더 보기 좋게 확인할 수 있습니다. 특히 리스트와 딕셔너리에 유용하고, 긴 답변 문자열도 화면에 여러 줄로 나누어 보여줄 수 있습니다.

```python
from pprint import pprint

# 앞에서 실행한 체인의 답변 출력
pprint(answer, width=80)
```

여기서 `width=80`은 권장 줄 너비이지 엄격한 제한은 아닙니다. 표시 방식만 달라지고 원래 답변은 그대로 남습니다. `pprint`는 Python 표현 방식으로 출력하므로 문자열에 따옴표가 붙고, 괄호나 이스케이프된 줄바꿈이 보일 수도 있습니다. 일반 문장을 줄바꿈해서 보여주는 것과는 조금 다릅니다.
