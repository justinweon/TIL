# 0901 TIL | 시퀀스 모델과 학습 기초, 데이터베이스 구조

문장을 번역하려면 단어의 뜻뿐 아니라 앞뒤 관계도 전달해야 해요. 이번 노트는 그 정보를 인코더와 디코더가 주고받는 방식에서 시작해, 어텐션과 트랜스포머가 무엇을 바꾸었는지 연결해 봅니다. 같은 날짜의 다른 원문에는 머신러닝 기초와 데이터베이스 구조가 있어 함께 담았습니다. 두 분야를 억지로 하나의 처리 과정으로 묶지는 않고, 각각의 학습 흐름을 유지했어요.

## 1. Seq2Seq는 읽는 과정과 만드는 과정을 나눠요

Seq2Seq(sequence-to-sequence)는 입력 시퀀스를 다른 길이의 출력 시퀀스로 바꾸는 구조예요. 번역과 요약처럼 입력과 출력의 길이가 꼭 같지 않은 작업에 쓰입니다. 여기서 다루는 기본형은 두 순환 신경망으로 구성됩니다.

- 인코더는 입력을 순서대로 읽고 상태를 갱신해요.
- 디코더는 인코더가 전달한 상태를 출발점으로 삼아 출력 토큰을 하나씩 예측해요.

LSTM 인코더는 은닉 상태 `h`와 셀 상태 `c`를 함께 갱신합니다. 셀 상태는 오래 유지할 정보를 전달하는 경로이고, 은닉 상태는 현재 시점의 출력 표현이에요. 기본 LSTM Seq2Seq에서는 최종 `(h, c)`를 디코더의 초기 상태로 넘길 수 있습니다.

> 바로잡기: 시그모이드가 셀 상태와 은닉 상태를 ‘분류’하는 것은 아니에요. 시그모이드는 게이트의 통과 비율을 정합니다. 또 컨텍스트 벡터를 언제나 ‘장기 기억과 단기 기억을 합친 하나의 벡터’라고 정의하지는 않아요. 기본 RNN에서는 마지막 은닉 상태를 가리킬 수 있고, LSTM 구현에서는 두 상태를 별도로 전달합니다. 어느 쪽도 문장의 모든 정보를 손실 없이 저장한다는 뜻은 아닙니다.

인코더는 입력 시퀀스를 한 번 훑지만, 그 안에서는 입력 길이만큼 순환 연산을 합니다. 디코더는 출력 토큰마다 다시 계산해요. `<sos>`는 생성을 시작하는 신호이고, `<eos>`는 종료 신호입니다. 종료 토큰을 예측하지 못할 수도 있어 추론에는 최대 생성 길이도 둡니다.

## 2. 학습 중에는 정답을 다음 입력으로 줄 수 있어요

디코더가 앞에서 틀린 토큰을 다음 입력으로 계속 사용하면 이후 예측도 영향을 받아요. Teacher Forcing은 학습할 때 이전 시점의 정답 토큰을 다음 입력으로 넣는 방법입니다.

| 예측 시점 | 입력으로 주는 정답 토큰 | 이번에 맞혀야 하는 토큰 |
|---|---|---|
| 첫 번째 | `<sos>` | 나는 |
| 두 번째 | 나는 | 코딩을 |
| 세 번째 | 코딩을 | 좋아한다 |
| 네 번째 | 좋아한다 | `<eos>` |

두 번째 예측이 틀려도 세 번째 입력에는 정답인 ‘코딩을’을 줍니다. 원문의 설명은 이 입력과 예측 시점이 섞여 있어 위처럼 정리했어요. `teacher_forcing_ratio`는 정답을 다음 입력으로 사용할 비율입니다. 추론에서는 정답을 모르므로 자신이 생성한 토큰을 사용합니다. 이 학습·추론 조건의 차이 때문에 Teacher Forcing만으로 오류 누적이 완전히 사라지는 것은 아니에요.

## 3. 토큰 인덱스에서 학습 루프까지 이어 보기

문자열은 먼저 토큰으로 나누고, 토큰을 정수 인덱스로 바꿉니다. `nn.Embedding`은 이 인덱스로 학습 가능한 밀집 벡터를 찾아요. 원핫 벡터 전체를 매번 만들 필요가 없어 어휘가 클 때 효율적입니다. 정답 표현은 모델 종류만으로 결정되지 않고 손실 함수의 입력 규약에 따라 정해집니다.

다음은 원문의 어휘 사전 코드를 문장 단위 데이터에도 맞도록 고친 예시입니다. `pairs`는 `(입력 문장, 정답 문장)` 문자열 쌍의 목록이라는 전제가 있어요. 공백 분리는 교육용 선택이며, 실제 언어·모델에 맞는 토크나이저로 대체해야 합니다.

```python
# pairs는 외부에서 준비한 (입력 문장, 정답 문장) 목록입니다.
src_tokens = sorted({token for src, _ in pairs for token in src.split()})
tgt_tokens = sorted({token for _, tgt in pairs for token in tgt.split()})

src_words = ["<pad>", "<unk>"] + src_tokens
tgt_words = ["<pad>", "<unk>", "<sos>", "<eos>"] + tgt_tokens
src_w2i = {word: i for i, word in enumerate(src_words)}
src_i2w = {i: word for word, i in src_w2i.items()}
tgt_w2i = {word: i for i, word in enumerate(tgt_words)}
tgt_i2w = {i: word for word, i in tgt_w2i.items()}
```

> 코드 수정: 원문의 `set(p[0] for p in pairs)`는 `p[0]`가 문장이면 문장 전체에 인덱스를 줍니다. 단어 사전을 만들려면 먼저 토큰화해야 해요. 미등록 토큰용 `<unk>`도 추가했습니다. 실제 데이터에 특수 토큰 문자열 자체가 포함되면 중복되지 않도록 별도 처리해야 합니다.

아래는 원문의 `EncoderLSTM`, `DecoderLSTM`과 `pass`로 남아 있던 통합·학습·추론 틀을 연결한 교육용 재구성 코드입니다. 원래 틀 자체가 완성된 프로그램은 아니었어요. 배치는 `[배치 크기, 길이]` 형태의 정수 텐서이고, 정답은 `<sos>`로 시작해 `<eos>`를 포함한다고 가정합니다. 입력은 패딩 없는 동일 길이 배치로 제한합니다. 가변 길이 입력이라면 `pack_padded_sequence` 등으로 실제 길이를 반영해야 하며, 이 예시에는 그 처리가 없습니다.

```python
import torch
import torch.nn as nn
from torch.utils.data import DataLoader  # 데이터셋 구성 후 배치를 만들 때 사용합니다.


class EncoderLSTM(nn.Module):
    def __init__(self, input_size, embed_size, hidden_size):
        super().__init__()
        self.embedding = nn.Embedding(input_size, embed_size, padding_idx=0)
        self.lstm = nn.LSTM(embed_size, hidden_size, batch_first=True)

    def forward(self, x):
        embedded = self.embedding(x)
        _, (hidden, cell) = self.lstm(embedded)
        return hidden, cell


class DecoderLSTM(nn.Module):
    def __init__(self, output_size, embed_size, hidden_size):
        super().__init__()
        self.embedding = nn.Embedding(output_size, embed_size, padding_idx=0)
        self.lstm = nn.LSTM(embed_size, hidden_size, batch_first=True)
        self.output = nn.Linear(hidden_size, output_size)

    def forward(self, x, hidden_state):
        # x: [배치 크기, 1]
        embedded = self.embedding(x)
        output, state = self.lstm(embedded, hidden_state)
        logits = self.output(output.squeeze(1))
        return logits, state


class Seq2Seq(nn.Module):
    def __init__(self, encoder, decoder):
        super().__init__()
        self.encoder = encoder
        self.decoder = decoder

    def forward(self, source, target, teacher_forcing_ratio=0.5):
        state = self.encoder(source)
        token = target[:, :1]  # <sos>
        predictions = []
        for t in range(1, target.size(1)):
            logits, state = self.decoder(token, state)
            predictions.append(logits)
            use_teacher = torch.rand(()).item() < teacher_forcing_ratio
            token = target[:, t:t + 1] if use_teacher else logits.argmax(-1, keepdim=True)
        return torch.stack(predictions, dim=1)


def train_epoch(model, iterator, optimizer, criterion):
    model.train()
    device = next(model.parameters()).device
    for source, target in iterator:
        source, target = source.to(device), target.to(device)
        optimizer.zero_grad()
        output = model(source, target)
        # <sos> 다음 토큰부터 예측하므로 정답도 한 칸 이동합니다.
        loss = criterion(
            output.reshape(-1, output.size(-1)),
            target[:, 1:].reshape(-1),
        )
        loss.backward()
        optimizer.step()


@torch.no_grad()
def translate(model, source_sentence, vocab, max_length=50):
    # source_sentence는 이미 인덱스로 변환한 [1, 입력 길이] 텐서입니다.
    model.eval()
    device = next(model.parameters()).device
    source_sentence = source_sentence.to(device)
    state = model.encoder(source_sentence)
    token = torch.tensor([[vocab["<sos>"]]], device=device)
    translation = []
    for _ in range(max_length):
        logits, state = model.decoder(token, state)
        token = logits.argmax(-1, keepdim=True)
        index = token.item()
        if index == vocab["<eos>"]:
            break
        translation.append(index)
    return translation


# 대상 어휘 사전에서 <pad>가 0이라는 전제입니다.
criterion = nn.CrossEntropyLoss(ignore_index=0)
```

`nn.Linear`의 결과는 확률이 아닌 로짓입니다. `CrossEntropyLoss`에 넣기 전에 별도로 softmax를 적용하지 않아요. 반환값 `[배치, 정답 길이-1, 어휘 수]`와 정답을 펼쳐 손실 함수의 형태에 맞춥니다. 원문의 `loss = criterion(output, target)`는 시점 이동과 차원 처리가 빠져 있어 수정했습니다. 추론 코드의 정의되지 않은 전역 `encoder`, `decoder`도 `model.encoder`, `model.decoder`로 연결했어요.

데이터셋, 모델 생성, 옵티마이저 설정은 제공하지 않았습니다. 원문의 생략 기호가 들어간 사전과 중복된 `pass` 클래스는 위 설명과 재구성 코드로 대체했으며, 학습 결과나 번역 결과를 만들어 넣지는 않았어요.

## 4. 고정된 기억의 한계에서 어텐션으로

기본 Seq2Seq는 입력을 고정 크기 상태에 압축합니다. 문장이 길고 복잡해질수록 필요한 정보를 충분히 전달하기 어려워요. 이것이 고정 컨텍스트의 병목입니다. 순환 구조에서 먼 시점까지 정보를 전해야 하는 장기 의존성 문제와 연결되지만, 두 개념이 완전히 같은 것은 아닙니다.

어텐션을 붙이면 인코더의 모든 시점별 은닉 상태를 보관하고, 디코더가 토큰을 만들 때마다 필요한 부분을 다시 참조합니다. 현재 디코더 상태를 질의 `Q`, 참조 대상을 비교하는 표현을 키 `K`, 실제로 모아 올 정보 표현을 값 `V`로 볼 수 있어요.

1. `Q`와 `K`의 관련도 점수를 구합니다.
2. softmax로 키 방향의 가중치를 정규화합니다.
3. 각 `V`에 가중치를 곱한 뒤 더해 컨텍스트를 만듭니다.

```text
점수 → softmax → 어텐션 가중치
컨텍스트 = 각 값 벡터에 해당 가중치를 곱한 결과의 합
```

스케일 점곱 어텐션은 다음 식으로 표현합니다.

$$
\operatorname{Attention}(Q,K,V)
=\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

`d_k`는 키 벡터의 차원입니다. 내적 값이 너무 커져 softmax가 과도하게 치우치는 것을 줄이려고 그 제곱근으로 나눕니다. 가중치는 학습된 표현과 현재 입력에 따라 계산되는 값이지, 단어마다 영구적으로 붙은 고정 중요도가 아니에요.

> 바로잡기: 어텐션은 ‘가중치들의 합’만으로 컨텍스트를 만들지 않습니다. **값 벡터의 가중합**을 만듭니다. RNN에 어텐션을 추가해도 RNN의 은닉 상태 갱신은 계속됩니다. 모든 상태를 참조할 수 있다는 사실이 정보 손실이나 긴 문장 문제의 완전한 해결을 보장하지도 않아요.

기본 Seq2Seq의 입력 요약은 생성 중 고정된 출발 정보이지만, 어텐션 컨텍스트는 출력 시점에 따라 달라집니다. 이때 기본 디코더의 상태까지 고정된다는 뜻은 아니에요. 디코더 상태는 토큰을 생성하며 계속 갱신됩니다.

## 5. 트랜스포머는 관계를 병렬로 계산해요

RNN 기반 어텐션에는 시간축의 순환 계산이 남아 있습니다. 트랜스포머는 이를 제거하고 self-attention으로 입력 토큰끼리의 관계를 계산해요. 학습 시 여러 위치를 행렬 연산으로 함께 처리할 수 있다는 점이 차이입니다.

| 구조 | 입력 정보의 전달 | 시간축 계산과 주의점 |
|---|---|---|
| 기본 RNN/LSTM Seq2Seq | 최종 상태로 압축 | 순환 의존성이 있어 시점별 계산이 필요해요. |
| RNN Seq2Seq + Attention | 모든 인코더 상태에서 시점별 컨텍스트 생성 | 정보 참조는 개선되지만 순환 의존성은 남아요. |
| Transformer | self-attention으로 위치 간 정보 결합 | 학습의 위치별 병렬화가 가능해요. 자기회귀 생성은 여전히 토큰별로 진행합니다. |

> 바로잡기: RNN의 ‘병렬 처리 불가능’은 주로 시간축의 순환 의존성을 말합니다. 배치나 행렬 연산까지 불가능한 것은 아니에요. 트랜스포머 역시 전체 모델이 단 한 번의 행렬 곱으로 끝나거나 항상 완전 병렬로 생성하는 것은 아닙니다. 여러 층과 연산을 거치며, 긴 입력에서는 어텐션 메모리·연산 비용도 커집니다.

### 5.1 위치 정보와 여러 어텐션 헤드

위치 정보가 없는 self-attention만으로는 단어 순서를 충분히 구분하기 어렵습니다. 원래 트랜스포머는 임베딩에 사인·코사인 기반 위치 인코딩을 더했어요. 학습 가능한 위치 임베딩이나 다른 위치 표현 방식도 있으므로 모든 모델이 같은 방식은 아닙니다.

`Q`, `K`, `V`는 학습 가능한 선형 변환으로 만듭니다. Multi-head attention은 서로 다른 투영 공간에서 어텐션을 계산하고 결과를 연결한 뒤 출력 선형층으로 변환해요. 헤드가 다른 관계를 강조할 수 있지만, ‘첫 헤드는 주어-동사, 두 번째는 수식 관계’처럼 역할이 미리 지정되거나 완전히 분리되는 것은 아닙니다. 원문의 역할·비율 예시는 비유이지 측정 결과가 아니므로 수치 도식은 생략했습니다. 독립 모델의 결과를 합치는 앙상블과도 동일하지 않아요.

### 5.2 FFN, 잔차 연결, 층 정규화

어텐션이 위치 사이의 정보를 섞었다면 FFN은 각 위치의 표현을 비선형적으로 가공합니다. 같은 FFN 가중치를 모든 위치에 적용해요. 원문의 예시처럼 `512 → 2048 → 512` 선형층 사이에 ReLU를 둘 수 있습니다. 숫자는 구조 예시이며 모든 트랜스포머의 고정 규격은 아닙니다.

```text
어텐션 하위층 → 드롭아웃 → 입력과 잔차 덧셈 → 층 정규화
FFN 하위층 → 드롭아웃 → 해당 하위층 입력과 잔차 덧셈 → 층 정규화
```

이것은 원래 트랜스포머의 post-norm 흐름을 단순화한 것입니다. 정규화를 하위층 앞에 두는 pre-norm도 있어요. 잔차 연결 `x + F(x)`는 원래 표현과 기울기가 전달될 직접 경로를 제공합니다. 층 정규화는 보통 각 토큰의 특성 차원에서 평균과 분산을 구해 정규화하고, 학습 가능한 크기·이동 파라미터를 적용합니다.

$$
\operatorname{LayerNorm}(x)
=\gamma\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta
$$

> 바로잡기: 드롭아웃 때문에 값이 계속 작아져서 잔차 연결로 ‘증폭’해야 한다는 설명은 부정확해요. 일반적인 드롭아웃은 학습 중 살아남은 값을 보정합니다. 잔차 연결의 목적은 단순 증폭이 아니라 정보와 기울기의 전달을 돕는 데 있습니다. 층 정규화도 값을 항상 `-2~2`에 가두지 않습니다. 원문의 대략적인 정규화 수치와 출력 예시는 검증된 계산 결과로 옮기지 않고 정확한 식으로 대체했습니다.

### 5.3 디코더의 마스크와 교차 어텐션

디코더의 causal masked self-attention은 현재 위치보다 미래의 정답 토큰을 참조하지 못하게 합니다. 보통 softmax 전에 금지된 위치의 점수에 음의 무한대에 해당하는 값을 적용하여, 정규화 후 그 가중치가 0이 되도록 해요.

> 바로잡기: 마스크는 답변의 다양성을 만들거나 다음 단어 예측 자체를 막기 위한 장치가 아닙니다. 미래 정답을 미리 보는 누수를 막아 다음 토큰 예측 조건을 지키는 장치예요.

인코더-디코더 트랜스포머의 cross-attention에서는 디코더 표현이 `Q`, 인코더 출력이 `K`와 `V`가 됩니다. 출력 문장을 만드는 현재 상태가 입력 문장의 관련 부분을 찾는 관계입니다. 트랜스포머는 ‘오직 어텐션만’ 있는 모델이 아니라 FFN, 정규화, 잔차 연결 등을 함께 사용하는 구조예요.

## 6. 같은 날짜의 기초 학습: 손실과 일반화

두 번째 0901 원문은 모델을 학습시키는 기본 개념부터 짚습니다. 앞의 신경망 코드에서 `loss.backward()`와 `optimizer.step()`이 나뉘어 있던 이유도 여기서 이해할 수 있어요.

손실 함수는 예측과 정답의 차이를 수치화하고, 역전파는 각 파라미터에 대한 손실의 기울기를 구합니다. 옵티마이저가 그 기울기를 사용해 가중치를 갱신해요. 단순 경사하강법의 갱신은 `파라미터 ← 파라미터 - 학습률 × 기울기`입니다. 가중치는 학습되는 파라미터이고, 학습률·규제 강도 등은 사용자가 정하는 하이퍼파라미터예요.

학습률이 너무 크면 최솟값 주변을 지나치거나 발산할 수 있고, 너무 작으면 학습이 느려질 수 있습니다. 비볼록 손실의 지역 최솟값 문제를 큰 학습률 때문이라고만 설명할 수는 없어요. 경사하강법이 언제나 전역 최솟값을 찾는 것도 아닙니다.

| 학습 준비 | 쓰는 이유와 주의점 |
|---|---|
| `MinMaxScaler` | 훈련 자료의 최솟값·최댓값으로 범위를 조절해요. 분산·표준편차를 기준으로 계산하지 않습니다. |
| `StandardScaler` | 훈련 자료의 평균·표준편차로 표준화해요. 스케일에 민감한 최적화·규제에서 도움이 됩니다. |
| 훈련·검증·테스트 분리 | 훈련은 파라미터 학습, 검증은 설정 선택, 테스트는 최종 평가에 사용해요. |
| K-Fold 교차검증 | 여러 분할에서 성능을 평가해요. 각 폴드의 훈련 부분에만 전처리를 `fit`해야 합니다. |

스케일링은 모든 모델에 무조건 필수인 것은 아니지만, 경사 기반 모델에서 특성 단위를 맞추는 데 유용합니다. `Pipeline`을 사용하면 교차검증 안에서 스케일러를 훈련 부분에만 학습시키기 쉬워요. 무작위 섞기도 항상 정답은 아닙니다. 시계열은 시간 순서를, 동일 개체가 반복되는 데이터는 그룹 경계를 지켜야 누수를 막을 수 있어요.

### 6.1 다중 회귀, 다항 특성, 규제

다중 선형 회귀는 여러 특성으로 연속적인 값을 예측합니다. 특성끼리 강하게 연관되면 다중공선성으로 계수 추정이 불안정해질 수 있고, VIF(분산팽창계수)는 이를 살펴보는 지표입니다.

특성 공학은 기존 변수를 변환하거나 조합하는 작업이에요. 다항 특성은 입력에 대한 비선형 패턴을 표현할 수 있게 하지만, 특성 수와 상관관계를 늘려 과적합·다중공선성을 오히려 키울 수도 있습니다. 그래서 모델 복잡도와 검증 성능을 함께 봐야 해요.

- Ridge는 L2 페널티로 계수를 축소합니다.
- Lasso는 L1 페널티로 일부 계수를 0으로 만들어 특성 선택 효과를 낼 수 있어요.
- `alpha`가 커지면 해당 모델의 규제가 강해집니다. 계수를 공정하게 비교하려면 특성 스케일도 고려해야 해요.

왜도가 큰 값에 로그 변환을 적용하는 것과, `alpha` 후보를 로그 간격으로 탐색하는 것은 다른 작업입니다. 전자는 데이터 분포를 바꾸고 후자는 탐색 간격을 정해요. 로그 변환은 0·음수 처리와 데이터 의미를 먼저 확인해야 합니다.

### 6.2 분류 확률과 정답 형식

로지스틱 회귀는 입력의 선형 결합인 로짓을 확률로 바꾸는 분류 모델입니다. 이진 분류에서는 sigmoid, 상호 배타적인 다중 클래스 분류에서는 softmax를 사용할 수 있어요. 이미 별도로 학습한 선형 회귀 모델의 예측에 활성화 함수만 붙인다는 뜻은 아닙니다.

| 문제와 정답 표현 | 손실 개념 |
|---|---|
| 이진 분류, 0 또는 1 | BCE |
| 다중 분류, 원핫 정답 | Categorical Cross Entropy |
| 다중 분류, 정수 클래스 정답 | Sparse Categorical Cross Entropy |

원핫과 정수 타깃은 같은 범주형 교차 엔트로피를 표현하는 다른 방식입니다. 다만 함수 이름과 입력 형식은 프레임워크마다 달라요. PyTorch의 `CrossEntropyLoss`는 보통 로짓과 정수 클래스 타깃을 받습니다. BCE는 정답에 낮은 확률을 줄수록 손실이 커집니다.

범주형 **입력 특성**에 정수 번호를 그대로 넣으면 원치 않는 크기·순서 관계가 생길 수 있어 원핫 인코딩을 고려합니다. 반면 분류의 **정답 인덱스**에는 같은 논리를 그대로 적용하지 않아요. 절편을 둔 선형 모델에 모든 더미 열을 넣으면 완전 다중공선성이 생길 수 있어 한 범주를 기준으로 빼기도 합니다. 모든 모델에서 무조건 한 열을 제거해야 한다는 뜻은 아닙니다.

### 6.3 심층 신경망과 순환 신경망의 학습

단층 퍼셉트론은 선형 결정 경계를 만들고, MLP는 은닉층과 비선형 활성화 함수를 통해 더 복잡한 관계를 표현합니다. 선형층만 여러 개 쌓으면 전체도 선형 변환이므로 비선형성이 필요해요. ReLU는 양수 구간의 기울기를 유지해 sigmoid의 포화로 인한 기울기 소실을 완화하지만, 모든 기울기 문제를 해결하지는 않습니다. 음수 구간에서 뉴런이 계속 비활성화되는 문제도 있어요.

미니배치는 메모리 부담을 낮추고 한 번의 전체 데이터 순회 안에서 여러 번 갱신할 수 있게 합니다. 대신 배치마다 추정한 기울기에 잡음이 있으므로 항상 더 매끄럽거나 안정적인 것은 아닙니다. 모델이 너무 단순하거나 덜 학습하면 과소적합, 훈련 자료의 잡음까지 맞추고 새 자료에서 성능이 떨어지면 과적합을 의심해요. 드롭아웃과 검증 지표 기반 조기종료는 이를 완화하는 방법이며, 조기종료는 보통 `patience`를 두고 가장 좋은 검증 시점의 가중치를 선택합니다. 최적 모델을 자동 보장하는 장치는 아니에요.

단어 임베딩은 희소한 원핫 표현 대신 인덱스에 해당하는 밀집 벡터를 조회합니다. 임베딩 행렬도 역전파로 학습돼요. 원문의 ‘차원의 저주’ 영문은 `Curse of Dimensionality`가 맞습니다. 원핫은 고차원·희소 표현을 만들지만 그것만으로 성능 저하가 항상 발생한다고 단정하지는 않습니다.

RNN은 시점마다 같은 가중치를 공유하면서 입력과 이전 은닉 상태를 결합합니다. 기본 tanh RNN에서는 은닉 출력이 `-1~1` 범위지만, 긴 시퀀스를 역전파할 때 기울기 소실·폭발이 생길 수 있어요. LSTM의 forget·input·output 게이트는 셀 상태와 은닉 상태의 정보 흐름을 조절해 이를 완화합니다. 둘은 구분되지만 서로 연관되어 계산됩니다. 패딩 토큰은 배치 길이를 맞추기 위한 것이므로 손실·어텐션 마스크와 실제 길이 처리에서 제외해야 합니다.

## 7. 데이터베이스에서는 구조와 행을 구분해요

신경망 학습과 별개로, 같은 날짜에는 SQL로 데이터 구조를 정의하고 행을 조작하는 기초도 다뤘습니다. DDL은 `CREATE`, `ALTER`, `DROP`처럼 테이블·인덱스·타입 등의 구조를 정의하는 명령이고, DML은 `INSERT`, `UPDATE`, `DELETE`처럼 행을 조작하는 명령이에요.

> 바로잡기: ‘DDL은 롤백할 수 없고 DML만 가능하다’는 설명은 PostgreSQL에 맞지 않습니다. PostgreSQL의 많은 DDL과 `TRUNCATE`는 트랜잭션 안에서 롤백할 수 있습니다. 일부 명령은 예외이고 DBMS별 동작도 달라요. `DELETE FROM 테이블`은 테이블 자체가 아니라 행을 지우며, `DROP TABLE`이 구조를 삭제합니다.

`ALTER TABLE`은 새 테이블 추가가 아니라 기존 테이블 구조 수정입니다. 아래는 원문의 문법 조각을 PostgreSQL 형식으로 정리한 **독립적인 구문 예시**예요. 같은 순서로 모두 실행하는 스크립트가 아니며, 테이블·열의 존재와 기존 데이터의 제약 충족 여부를 확인해야 합니다.

```sql
ALTER TABLE members ADD COLUMN nickname VARCHAR(50);
ALTER TABLE members RENAME COLUMN nickname TO display_name;
ALTER TABLE members DROP COLUMN display_name;
ALTER TABLE members ALTER COLUMN age TYPE BIGINT USING age::BIGINT;
ALTER TABLE members ALTER COLUMN age SET DEFAULT 0;
ALTER TABLE members ALTER COLUMN age DROP DEFAULT;
ALTER TABLE members ALTER COLUMN age SET NOT NULL;
ALTER TABLE members ALTER COLUMN age DROP NOT NULL;
ALTER TABLE members ADD CONSTRAINT members_age_check CHECK (age >= 0);
ALTER TABLE members DROP CONSTRAINT members_age_check;
ALTER TABLE members ADD CONSTRAINT members_email_unique UNIQUE (email);
ALTER TABLE orders ADD CONSTRAINT orders_member_fk
    FOREIGN KEY (member_id) REFERENCES members (id) ON DELETE CASCADE;
```

`PRIMARY KEY`, `UNIQUE`, `CHECK`, `FOREIGN KEY` 같은 이름 있는 제약은 `ALTER TABLE ... ADD CONSTRAINT`로 추가합니다. `ON DELETE CASCADE`는 부모 삭제 시 참조하는 자식 행도 삭제하고, `SET NULL`은 자식 외래키를 NULL로 바꿉니다. 후자는 해당 열이 NULL을 허용해야 해요. 기본키 추가는 `ALTER TABLE members ADD CONSTRAINT members_pk PRIMARY KEY (id);` 형태이며, 기존 기본키가 없어야 합니다.

```sql
-- members(id, name)이 준비되어 있다고 가정한 DML 구문 예시입니다.
INSERT INTO members (id, name) VALUES (1, '김철수');
UPDATE members SET name = '김영희' WHERE id = 1;
DELETE FROM members WHERE id = 1;
```

`UPDATE`와 `DELETE`에서 `WHERE`를 생략하면 대상이 전체 행이 됩니다. `TRUNCATE TABLE members;`도 전체 행을 비우므로 단순 조회와 혼동하지 않아야 해요.

ERD에서는 회원 한 명이 주문 여러 건을 갖는 `1:N`, 회원과 별도 상세 프로필을 연결하는 `1:1`을 구분합니다. 주문이 아직 없는 회원을 허용하는지는 최소 참여 수의 문제예요. `N`이라는 표기만으로 항상 ‘0개 이상’이 정해지는 것은 아닙니다. 원문의 ‘주문상품’은 이름만 있어 필드나 관계를 임의로 확정하지 않았습니다.

제목이 모두 `0901`인 서로 다른 두 페이지를 이 날짜의 한 파일에 담았습니다. 날짜를 이동하지 않았고 별도 요약 페이지는 사용하지 않았어요. 반복된 구조 비교·ASCII 설명과 비어 있는 탭은 합쳤으며, 부정확한 수치 도식은 계산된 결과처럼 보이지 않도록 식과 설명으로 대체했습니다.

Python 코드는 문법 검사 대상입니다. 데이터셋 준비, 텐서 차원별 실제 실행, 모델 학습·추론과 SQL 실행은 수행하지 않았으므로 실행 성공이나 성능을 뜻하지 않습니다.
