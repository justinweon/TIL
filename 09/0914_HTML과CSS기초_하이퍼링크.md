# 0914 TIL: HTML·CSS 기초와 하이퍼링크

웹페이지에는 제목과 본문이 있고, 색상과 배치가 있으며, 버튼을 눌렀을 때 일어나는 동작도 있습니다. 오늘은 이 역할을 나누어 이해한 뒤, HTML 태그로 문서를 구성하고 링크로 다른 문서와 연결하는 방법을 배웠습니다.

## 1. 웹페이지를 구성하는 세 가지 기술

| 기술 | 주된 역할 | 예시 |
|---|---|---|
| HTML | 문서의 구조와 의미 | 제목, 문단, 링크, 버튼 |
| CSS | 표현과 배치 | 색상, 글꼴, 간격, 레이아웃 |
| JavaScript | 프로그램 로직과 상호작용 | 클릭 처리, 데이터를 받아 화면 갱신 |

‘HTML은 뼈대, CSS는 스타일, JavaScript는 동작’이라고 기억하면 출발하기 좋습니다. 다만 CSS도 애니메이션을 만들 수 있으므로 움직이는 모든 요소에 JavaScript가 필요한 것은 아닙니다.

### 1.1 HTML: 문서를 구조화하고 연결하기

HTML은 **HyperText Markup Language**의 약자입니다.

하이퍼텍스트는 링크를 통해 다른 문서나 문서의 다른 부분으로 이동할 수 있는 텍스트 구조를 뜻합니다. 전자책에도 활용할 수 있지만, 하이퍼텍스트 자체가 전자책 전용 언어인 것은 아닙니다.

마크업은 내용에 표식을 붙여 구조와 의미를 나타내는 방식입니다. HTML에서는 태그로 ‘이것은 제목’, ‘이것은 문단’, ‘이것은 링크’라고 표시합니다.

```html
<h1>오늘의 학습 기록</h1>
<p>HTML로 문서의 구조를 표현하는 방법을 배웠습니다.</p>
<a href="https://developer.mozilla.org/ko/">다른 문서로 이동하기</a>
```

대부분은 `<태그>내용</태그>` 형태로 작성합니다. 시작 태그, 내용, 종료 태그를 합쳐 **요소(element)**라고 부릅니다. `<img>`나 `<br>`처럼 종료 태그가 없는 요소도 있습니다.

태그 자체가 통신을 뜻하는 것은 아닙니다. 태그는 문서의 구조와 의미를 표시하는 문법이고, 브라우저가 그 문서를 해석합니다.

### 1.2 CSS: 같은 문서를 어떻게 보여줄까요?

CSS는 **Cascading Style Sheets**의 약자입니다. HTML로 구성한 문서를 어떤 색상과 크기, 배치로 보여줄지 지정합니다.

메모에서는 부모의 스타일이 자식에게 전달되는 모습을 캐스케이드와 연결했지만, **캐스케이드와 상속은 구분해야 합니다.**

- **캐스케이드(cascade):** 같은 요소의 같은 속성에 여러 스타일 선언이 적용될 때 우선순위에 따라 사용할 값을 결정하는 과정입니다.
- **상속(inheritance):** 부모 요소의 일부 속성값이 자식 요소로 전달되는 방식입니다.

예를 들어 글자색은 보통 상속되지만 여백이나 테두리가 모두 자동으로 상속되는 것은 아닙니다. SQL의 연쇄 삭제와도 다른 개념입니다.

```css
body {
  color: navy;
}

/* 부모에게서 물려받는 색 대신 이 요소에 지정한 색을 사용합니다. */
strong {
  color: crimson;
}
```

## 2. 웹 표준: 다른 브라우저에서도 사용할 수 있도록

사용자는 Chrome, Safari, Firefox 등 서로 다른 브라우저로 같은 페이지를 방문합니다. 개발자 입장에서는 브라우저마다 완전히 다른 코드를 작성하지 않고도 서비스를 제공할 수 있어야겠죠.

웹 표준은 HTML, CSS, JavaScript와 관련 웹 기술이 공통된 방식으로 동작하도록 정한 규격입니다. 표준을 지키면 브라우저 사이의 호환성을 확보하는 데 도움이 됩니다.

다만 모든 환경에서 픽셀 단위로 완전히 같은 화면이 보장되는 것은 아닙니다. 브라우저의 기능 지원, 기본 스타일, 운영체제의 글꼴 등에 차이가 있을 수 있습니다. 의미와 기능이 호환되도록 만들고 필요한 환경에서 확인하는 것이 중요합니다.

‘2015년 이후 호환성 문제가 해결되었다’처럼 한 시점으로 나누기보다는, 호환성이 개선되어 왔지만 기능별 지원 차이는 여전히 확인해야 한다고 이해하는 편이 정확합니다.

## 3. HTML 태그: 모양보다 의미부터 이해하기

### 3.1 제목과 본문 구분하기

제목은 글자를 크게 만드는 장치만은 아닙니다. 문서의 주요 내용과 하위 구조를 전달하며, 사용자와 스크린 리더 등이 내용을 탐색하는 데 도움을 줍니다. 제목 단계는 글자 크기 취향이 아니라 문서의 계층에 맞춰 선택합니다.

| 태그 | 의미와 용도 |
|---|---|
| `<h1>`~`<h6>` | 제목의 단계. `<h1>`이 가장 높은 수준 |
| `<p>` | 하나의 문단 |
| `<b>` | 특별한 중요성 부여 없이 주의를 끄는 텍스트. 보통 굵게 표시 |
| `<strong>` | 강한 중요성·심각성·긴급성. 보통 굵게 표시 |
| `<i>` | 전문 용어, 다른 언어 표현 등 주변과 구별되는 텍스트. 보통 기울임꼴 |
| `<u>` | 철자 오류 표시 같은 비텍스트적 주석. 보통 밑줄 |
| `<del>` | 문서에서 삭제된 내용. 보통 취소선 |
| `<strike>` | 오래되어 더 이상 권장되지 않는 태그 |

`<b>`와 `<strong>`은 기본 모양이 비슷해도 의미는 다릅니다. 단순히 굵게 만들거나 밑줄을 긋는 등 모양만 바꾸려는 목적이라면 CSS로 표현할 수 있습니다.

`<strike>` 대신 삭제된 내용에는 `<del>`, 더 이상 정확하거나 관련 없는 내용에는 `<s>`를 사용할 수 있습니다.

`<p>`도 ‘문단 사이를 띄우는 도구’보다는 ‘문단을 표시하는 요소’입니다. 브라우저의 기본 여백 때문에 문단 사이가 벌어져 보이며, 간격은 CSS로 조절합니다.

### 3.2 주석으로 설명 남기기

```html
<!-- 이 부분은 문서의 주 제목입니다. -->
<h1>HTML 기초</h1>

<!-- <p>잠시 화면에서 제외한 문단입니다.</p> -->
```

주석 내용은 일반적인 페이지 화면에는 표시되지 않습니다. 하지만 소스 보기나 개발자 도구에서는 확인할 수 있으므로 비밀번호나 API 키를 숨기는 용도로 사용하면 안 됩니다.

### 3.3 블록과 인라인: 기본 배치 방식의 차이

문단은 보통 새 줄에서 시작하지만, 문장 안의 강조 표현은 글의 흐름을 이어갑니다. 이 차이를 설명할 때 블록과 인라인이라는 말을 사용합니다.

| 기본 배치 | 특징 | 예시 |
|---|---|---|
| 블록 | 일반적인 문서 흐름에서 새 줄을 시작하고 가로 공간을 넓게 사용 | `<p>`, `<div>`, 제목 요소 |
| 인라인 | 문장 흐름 안에서 내용에 필요한 공간을 사용하며 줄바꿈될 수 있음 | `<span>`, `<a>`, `<strong>` |

이는 기본적인 CSS 배치 방식에 대한 설명입니다. `display` 속성으로 바꿀 수 있지만, 배치를 바꾼다고 HTML 요소의 의미까지 달라지는 것은 아닙니다.

## 4. 하이퍼링크: 문서와 문서 연결하기

한 페이지의 내용을 구성했다면, 이제 다른 문서로 이동할 수 있게 연결할 수 있습니다. 이때 HTML의 하이퍼텍스트 역할이 드러납니다.

### 4.1 a 태그와 속성

링크에는 **`<a>` 태그(anchor)**를 사용합니다. 태그만으로는 목적지를 알 수 없으므로 `href` 속성에 이동할 주소를 지정합니다.

```html
<a href="http://www.naver.com">네이버로 이동</a>
```

`href`는 목적지이고, 태그 사이의 문구는 화면에 표시되는 링크 텍스트입니다. 속성(attribute)은 시작 태그 안에 `이름="값"` 형태로 추가하는 정보입니다.

코드에서는 문서 편집용 따옴표인 `“ ”` 대신 일반 따옴표 `" "`를 사용합니다. 붙여넣기 과정에서 생긴 `@url:` 표기와 백틱도 실제 주소에서 제거합니다.

### 4.2 절대 경로와 상대 경로

목적지는 전체 주소로 지정하거나 현재 문서를 기준으로 지정할 수 있습니다.

| 경로 방식 | 예시 | 의미 |
|---|---|---|
| 절대 URL | `https://example.com/docs/page.html` | 프로토콜과 호스트를 포함한 전체 주소 |
| 문서 기준 상대 경로 | `./child.html` | 현재 문서가 있는 디렉터리의 파일 |
| 상위 디렉터리 상대 경로 | `../child.html` | 한 단계 위 디렉터리의 파일 |
| 사이트 루트 기준 경로 | `/images/photo.png` | 웹사이트 최상위 경로를 기준으로 찾는 파일 |

일반적으로 `./`는 현재 문서가 있는 디렉터리, `../`는 그 위 디렉터리를 뜻합니다. `<base>` 요소로 기준 URL을 따로 설정한 문서에서는 그 기준을 따릅니다.

강의의 파일 배치를 단순화하면 다음과 같습니다.

```text
chapter01/
├── photo.png
└── sub1/
    └── sub2/
        └── 01-4.html
```

`01-4.html`에서 `photo.png`를 불러오려면 두 단계 위로 올라갑니다.

```html
<img src="../../photo.png" alt="예시 사진">
```

이 예제는 링크 이동이 아니라 이미지 불러오기이므로 `href` 대신 `src`를 사용합니다. `alt`는 이미지의 대체 텍스트입니다.

로컬 파일을 가리키는 `file:///C:/...` 주소도 있지만 다른 사용자의 컴퓨터에는 같은 파일이 없을 수 있습니다. 웹에 공개할 페이지에서는 사이트에서 접근 가능한 URL과 적절한 상대 경로를 사용해야 합니다.

경로 변경으로 연결이 끊어지는 문제는 절대 경로에만 있는 것은 아닙니다. 상대 경로도 파일 사이의 위치 관계가 달라지면 수정해야 합니다.

### 4.3 target: 어디에서 링크를 열까요?

`href`가 어디로 이동할지 정한다면, `target`은 어떤 탭이나 프레임에서 열지 정합니다.

| 값 | 동작 |
|---|---|
| `_self` | 현재 탐색 맥락에서 열기. 별도 설정이 없을 때 기본값 |
| `_blank` | 새 탭 또는 새 창에서 열기 |
| `_parent` | 현재 프레임의 바로 위 부모 탐색 맥락에서 열기 |
| `_top` | 프레임 계층의 가장 바깥쪽 탐색 맥락에서 열기 |
| 지정한 이름 | 해당 이름의 탭·창·프레임을 대상으로 열기 |

```html
<a href="http://www.naver.com" target="_blank" rel="noopener">
  네이버를 새 탭 또는 새 창에서 열기
</a>
```

`_blank`는 반드시 별도의 창을 만드는 것은 아닙니다. 브라우저 설정 등에 따라 새 탭으로 열릴 수 있습니다. 보충 예제의 `rel="noopener"`는 새 페이지가 `window.opener`로 원래 페이지를 참조하지 못하도록 명시합니다.

### 4.4 iframe: 페이지 안에 다른 문서 넣기

`iframe`은 현재 페이지 안에 다른 HTML 문서를 표시하는 요소입니다. 독립된 브라우저 프로그램이라기보다 페이지 안에 중첩된 탐색 맥락을 만든다고 이해하면 정확합니다.

태그 이름은 `<iframe:>`이 아니라 `<iframe>`입니다.

```html
<iframe
  name="child1"
  src="child.html"
  title="하위 문서"
  width="600"
  height="500">
</iframe>
```

| 속성 | 역할 |
|---|---|
| `src` | 처음 표시할 문서 주소 |
| `name` | 링크의 `target` 등에서 사용할 프레임 이름 |
| `title` | 프레임 내용을 설명하는 이름. 접근성에 도움 |
| `width`, `height` | 프레임 표시 크기 |

이름을 지정하면 링크를 클릭했을 때 해당 프레임 안의 문서를 바꿀 수 있습니다.

```html
<a href="another.html" target="child1">
  프레임 안에서 다른 문서 열기
</a>
```

부모와 최상위의 차이는 여러 단계로 중첩되었을 때 잘 보입니다.

```text
바깥쪽 페이지 A
└── iframe B
    └── iframe C
```

C 안의 링크를 클릭하면 `_self`는 C, `_parent`는 B, `_top`은 가장 바깥쪽 A에서 엽니다. 부모 프레임이 없다면 `_parent`와 `_top`은 `_self`처럼 동작합니다.
